# Toast notifications for actions and job lifecycle

Introduce a consistent toast notification stack and migrate the inconsistent mix of `alert()`, inline `Alert` banners, and silent successes to it.

## Requirements

- New `ToastProvider` mounted once at the app root, exposing a `useToast()` hook with `toast.success(msg)`, `toast.error(msg)`, `toast.info(msg)`, and `toast.promise(p, { loading, success, error })`.
- Toasts stack bottom-right, auto-dismiss after 4s (errors after 6s), max 3 visible at once, with a close button and a subtle progress bar. Keyboard accessible (Esc dismisses the focused toast).
- Migrate these existing flows to toasts: bulk actions in `BulkActionBar` (add to album / label / favorite / archive / restore / purge), share-link minted/revoked in `ShareModal` (currently uses clipboard copy without confirmation), copy-to-clipboard utilities, smart-album create/update/delete, sort/upload/process job started+completed (terminal events from the SSE stream).
- Replace every `alert(...)` and `window.confirm` for non-destructive operations with toast feedback. Keep `ConfirmDialog` for destructive confirmations (purge, delete album, etc.) — toast is for results, not prompts.
- i18n keys for every toast message (cs + en).
- The `Alert` component stays — it's still the right tool for persistent inline errors (form validation, page-level failures).

## Implementation Notes

- Pick a small dependency-free implementation or `react-hot-toast` (~3 KB) — author's call.
- Don't change endpoint payloads; only the UI feedback layer changes.
