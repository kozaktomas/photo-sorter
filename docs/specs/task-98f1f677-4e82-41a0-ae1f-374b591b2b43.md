# Photo update handler (own backend)

Add a native PUT handler at `/api/v1/photos/{uid}` that mutates the photo row in the local `photos` table instead of calling PhotoPrism's `EditPhoto`. Also add the corresponding batch endpoints used by the bulk action bar.

## Requirements

### Files

- `internal/web/handlers/photos.go` — add the update handler + batch handlers.
- `internal/web/handlers/photos_test.go` — extend tests.

### Endpoints

#### PUT `/api/v1/photos/{uid}`

Request JSON (all fields optional — only non-null fields are updated):

```json
{
  "title": "...",
  "description": "...",
  "notes": "...",
  "taken_at": "2024-06-15T14:30:00Z",
  "lat": 50.08, "lng": 14.43,
  "favorite": true,
  "private": false
}
```

Validation:
- `title`: ≤ 255 chars.
- `taken_at`: RFC3339; reject obviously-bogus years (< 1900 or > 2100).
- `lat` between -90 and 90; `lng` between -180 and 180; both must be present together.

Behaviour:
- Load existing photo (404 if missing or archived).
- Apply only the keys the client sent (use a JSON map + presence check; do not let zero-values clear fields unintentionally).
- Update `updated_at` to NOW.
- Return the updated photo.

Use `database.PhotoWriter.UpdatePhoto`.

#### POST `/api/v1/photos/batch/edit`

Already exists today via PhotoPrism. Rewrite to use the local repo. Request:

```json
{ "photo_uids": ["p123...", "p456..."], "favorite": true, "private": false }
```

Returns `{ "updated": N, "errors": [{photo_uid, error}] }`. Continue on per-photo errors (don't fail the whole batch).

#### POST `/api/v1/photos/batch/archive`

```json
{ "photo_uids": [...] }
```

Calls `repo.ArchivePhoto` for each. Same response shape.

#### POST `/api/v1/photos/batch/restore`

Mirror of archive — calls `repo.RestorePhoto`.

### Authorization

Block PUT/POST batch endpoints when the session user has `role = "viewer"`. Use a small helper `requireWriteRole(r) error` to be added in `face_helpers.go` or `common.go` (this can be wired against the future users table; for now read role from session context — if absent treat as admin to keep tests passing).

### Tests

- PUT with partial body updates only the provided fields, leaves the rest.
- PUT with invalid `taken_at`/`lat` → 400.
- Batch edit reports per-photo errors but keeps going on missing UIDs.
- Archive then restore round-trips correctly.
