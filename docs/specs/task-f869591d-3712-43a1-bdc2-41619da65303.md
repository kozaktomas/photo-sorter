# Database Export / Import CLI

Add a pair of CLI subcommands that let an operator dump the full photo-sorter PostgreSQL database to a single file and restore it on another machine. Photos themselves are NOT part of this command — the user backs up the `data/originals/` tree separately via rsync/borg/etc. This command covers the metadata side of disaster recovery: embeddings, faces, books, users, sessions, era_embeddings, photo rows, albums, labels, markers, subjects — everything that lives in the `photosorter` database.

## Requirements

### Common
- New Cobra command group `db` under the root CLI (sibling to `serve`, `albums`, `photo`, `cache`, etc.). Put the implementation in `cmd/db.go`.
- Both subcommands read `DATABASE_URL` from config (same loader used by `serve`). Fail with a clear error if `DATABASE_URL` is unset or malformed.
- Both subcommands shell out to the system `pg_dump` / `pg_restore` binaries. If the binary is not on `PATH`, print an actionable error (`pg_dump not found in PATH — install postgresql-client`).
- Parse `DATABASE_URL` once and convert it to the form expected by the libpq tools (set `PGHOST`, `PGPORT`, `PGUSER`, `PGPASSWORD`, `PGDATABASE` via env on the child process instead of putting credentials on the command line).
- Both subcommands stream child-process stdout/stderr live to the user (do not buffer) so the user sees progress.

### `photo-sorter db-export`
- Flags:
  - `--output, -o` (string) — destination file path. Default: `photosorter-YYYYMMDD-HHMMSS.sql.gz` in the current directory (UTC timestamp).
  - `--format` (string, default `custom`) — passes through to `pg_dump --format`. Allowed: `custom`, `plain`. Anything else: validation error.
  - `--no-compress` (bool, default false) — when true, skip gzipping for `plain` format. Ignored for `custom` (pg_dump's custom format is already compressed).
- Behavior:
  - For `plain` format: pipe `pg_dump` stdout through `gzip` (unless `--no-compress`) into the output file.
  - For `custom` format: write `pg_dump -Fc` output directly to the output file (already compressed; do not gzip).
  - On success, print: dump path, final file size (human-readable, e.g. `42.7 MiB`), and elapsed wall time.
  - If the output path already exists, refuse with a clear error unless `--force` is passed.

### `photo-sorter db-import`
- Flags:
  - `--input, -i` (string, required) — source dump file.
  - `--yes, -y` (bool, default false) — skip the interactive confirmation prompt.
  - `--drop-existing` (bool, default false) — when true, the import will first drop the public schema (`DROP SCHEMA public CASCADE; CREATE SCHEMA public;`) so a clean restore can run. When false, behave like `pg_restore --clean --if-exists` for custom format or rely on the SQL dump's own statements for plain format.
- Behavior:
  - Auto-detect dump format by file header: gzipped + first uncompressed bytes start with `PGDMP` → custom format; gzipped + starts with `--` or `SET` → plain SQL; not gzipped → same detection on raw bytes.
  - For `plain` format: stream the (optionally gunzipped) file into `psql` stdin.
  - For `custom` format: invoke `pg_restore --dbname=... --no-owner --no-privileges` (and `--clean --if-exists` unless `--drop-existing` is set). For gzipped custom dumps, gunzip to a temp file first (pg_restore needs a seekable file), then delete after.
  - Before doing anything destructive, connect to the DB and check whether the `embeddings` table exists with any rows. If yes, refuse unless `--yes` is passed. The prompt text should be: `Database <name> at <host> appears to contain data (N rows in embeddings). Importing will overwrite it. Type "yes" to continue:` and require literal `yes`.
  - On success, print a "next steps" block:
    ```
    Import complete.

    Next steps:
      1. Restart the photo-sorter server (HNSW indexes load at startup).
      2. If the imported DB came from a host with a different originals tree,
         verify STORAGE_ORIGINALS_PATH and re-run `photo-sorter cache build-thumbs`
         to regenerate thumbnails for any missing sizes.
      3. If face-search results look off, hit `POST /api/v1/process/rebuild-index`
         (Rebuild Index button in the UI) to rebuild the in-memory HNSW indexes
         from the freshly imported embeddings.
    ```

## Edge Cases
- Empty database export: pg_dump succeeds with a near-empty output; that's fine, print size as usual.
- DATABASE_URL with `sslmode=disable` query params: pass through correctly; libpq honors `PGSSLMODE` if set, but it's simpler to keep the query params and use the URL form for pg_dump (`pg_dump "$DATABASE_URL"`). Use this approach: pass the URL as a positional argument to pg_dump/pg_restore. This avoids the env var dance entirely. Update the spec mentally; do this.
- Interrupted dump: if `pg_dump` exits non-zero, delete the partial output file before returning the error (so users don't accidentally try to restore from a half-baked dump).
- Interrupted import: if `pg_restore`/`psql` exits non-zero, surface the exit code; do not attempt cleanup of the DB (it's the user's problem at that point).
- File extension hints: if `--output` ends in `.sql` and `--format` is `custom`, warn (but continue) — the file will not be plain SQL.
