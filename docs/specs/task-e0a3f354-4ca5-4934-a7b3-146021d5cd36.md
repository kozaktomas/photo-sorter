# Browse Page with Synchronized Map and Timeline

Add a new `/browse` page that lets users explore the photo library on a map and timeline simultaneously, with bidirectional filtering between the two views.

## Requirements

- New page at `/browse` accessible from the main navigation (alongside Photos, Albums, etc.).
- Layout: map on top (~60% height), timeline scrubber on the bottom (~40% height). On mobile, stack vertically.
- The map shows photos with GPS coordinates as clustered markers. Photos without GPS do not appear on the map but ARE still counted in the timeline.
- The timeline shows a histogram of photo counts by month across the available date range. The user can drag a range selector ("brush") to constrain the date range.
- Bidirectional sync:
  - Panning/zooming the map updates `min_lat`, `min_lng`, `max_lat`, `max_lng`, which constrain BOTH map results and the timeline histogram (so the histogram reflects only photos in the visible area).
  - Adjusting the timeline range updates `taken_from`/`taken_to`, which constrains BOTH map markers and the timeline.
- Click a cluster: show a side panel with the photos in the cluster, click-through to PhotoDetail.
- Click a single marker: show the photo in a side panel preview with a link to PhotoDetail.

## Backend

- Add `GET /api/v1/photos/histogram` endpoint that returns a date histogram. Query params:
  - `bucket`: `month` (default) or `year`.
  - All the same filters as `GET /api/v1/photos` (label_uid, subject_uid, favorite, taken_from, taken_to, geo bbox, q).
- Response: `{ buckets: [{ start: "2024-01-01", end: "2024-02-01", count: 42 }, ...], total: 1234, no_date_count: 12, no_gps_count: 89 }`.
- Add `GET /api/v1/photos/geo-points` endpoint that returns just `{uid, lat, lng}` arrays for all photos matching the same filter set, no pagination. The frontend uses this for client-side clustering. (Photos with NULL lat/lng are excluded.) Cap the result at 50,000 points and add a `truncated: bool` flag if exceeded.
- Both endpoints must use the same authentication and role checks as `/photos`.

## Frontend

- Use `react-leaflet` for the map with OpenStreetMap tiles. For clustering use `react-leaflet-cluster` or `leaflet.markercluster`.
- Use a charting library that supports interactive brushing on a histogram (recharts has BrushChart). Keep dependencies light.
- Update URL query params (`?min_lat=...&taken_from=...`) so views are bookmarkable and the back button works.
- Photos without GPS are shown as a "No location (N photos)" chip; clicking it opens a filtered photo list view.
- Czech + English i18n strings in `web/src/i18n/locales/{cs,en}/pages.json` under a new `browse` namespace.
- Add a "Browse" entry in the main nav with a globe/map icon.

## Edge Cases

- Empty library: friendly empty state with a tip to upload photos.
- No photos with GPS at all: hide the map (or show a small placeholder note "No photos have GPS coordinates yet"), keep the timeline.
- Very large date ranges (e.g. 1950–today): bucket by year by default if span > 5 years, by month otherwise.
- The timeline scrubber must be touch-friendly on mobile.
