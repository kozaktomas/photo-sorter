# User management API + admin endpoints

Add admin-only HTTP endpoints for managing users. UI for these endpoints is a separate frontend task; this one is backend + tests only.

This task assumes the `users` table, `UserReader`/`UserWriter`, `internal/auth`, and the `RequireRole` middleware already exist.

## Requirements

### Files

- `internal/web/handlers/users.go` — new file.
- `internal/web/handlers/users_test.go` — tests.
- Router wiring in `internal/web/router.go`.

### Endpoints (all behind `RequireRole("admin")`)

- `GET /api/v1/users` → `{ users: [User...] }` (sorted by username ASC).
- `POST /api/v1/users` → create user. Body: `{ username, password, display_name?, email?, role }`. Validates role ∈ {admin, editor, viewer}; password ≥ 8 chars; username matches `^[a-z0-9_.-]{3,64}$`. Returns the new user (no password). 409 if username taken.
- `GET /api/v1/users/{uid}` → single user.
- `PUT /api/v1/users/{uid}` → update display_name / email / role. Cannot change username (forbid in the handler).
- `POST /api/v1/users/{uid}/password` → set password. Body: `{ password }`. Re-validates length.
- `POST /api/v1/users/{uid}/disable` → toggle disabled. Body: `{ disabled: true|false }`.
- `DELETE /api/v1/users/{uid}` → hard-delete. Reject if the target is the LAST admin (run `ListUsers` and count remaining admins). Reject if `uid == AuthInfo.UserUID` (can't delete yourself).

### Self-service endpoint

- `GET /api/v1/me` — returns the current user (any logged-in role). Convenience for the frontend.
- `POST /api/v1/me/password` — change own password. Body: `{ current_password, new_password }`. Verify `current_password` against stored hash before applying. New password ≥ 8 chars.

### JSON shape

```json
{ "uid": "u...", "username": "kozak", "display_name": "Tomáš Kozák",
  "email": "...", "role": "admin", "disabled": false,
  "created_at": "...", "last_login_at": "..." }
```

Never include `password_hash`.

### Tests

- List users → 403 for non-admin.
- Create user as admin → 201, password is hashed in DB.
- Cannot create with weak password / invalid role / taken username.
- Delete last admin → 400 with explicit error.
- `/me` returns the current user.
- Password change with wrong current password → 401.

## Verification

- `make test` passes.
- `make lint`, `make build-go` pass.
- Manual sanity: admin can create an editor user, editor can hit `/api/v1/photos` but not `/api/v1/users`.
