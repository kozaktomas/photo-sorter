# Single-Binary .deb Release Pipeline

Ship photo-sorter as a single-binary `.deb` package buildable on tag push via GitHub Actions, targeted at Ubuntu / Debian servers. The frontend already embeds into the Go binary via `go:embed`, so "single binary" is a packaging question, not a refactor — the deb wraps that binary with a systemd unit, a sample env config, bundled book-typography fonts, and declared runtime dependencies.

Reference implementation to mirror in style and structure: `https://github.com/kozaktomas/teltonika-exporter` (same maintainer's existing pattern — `.goreleaser.yaml` + `deb/` directory + nfpm-driven deb build).

## Goals

After this task:
- `git tag v1.2.3 && git push --tags` triggers a GitHub Actions workflow that produces `photo-sorter_1.2.3_linux_amd64.deb` and `photo-sorter_1.2.3_linux_arm64.deb`, attaches them to a GitHub Release, and creates the release notes from commit history.
- `apt install ./photo-sorter_*.deb` on a clean Ubuntu 24.04 host:
  - Drops the binary at `/usr/bin/photo-sorter`.
  - Installs a systemd unit at `/lib/systemd/system/photo-sorter.service`.
  - Drops a sample env file at `/etc/photo-sorter/photo-sorter.env` (conffile — not overwritten on upgrade).
  - Installs bundled fonts under `/usr/local/share/fonts/photo-sorter/` and refreshes `fc-cache`.
  - Creates a system user `photo-sorter` and state directories `/var/lib/photo-sorter/{originals,cache}` owned by it.
  - Enables the systemd unit but does NOT start it (DATABASE_URL must be set first).
  - Pulls in all runtime tools (texlive, exiftool, heif-convert, dcraw, postgresql-client, fontconfig).
- `systemctl start photo-sorter` after the operator edits the env file → service runs.

## Requirements

### 1. `.goreleaser.yaml` at repo root

Model after the teltonika-exporter file. Concretely:

- `version: 2`.
- `before.hooks`: run `go mod tidy`, then build the frontend (`cd web && npm ci && npm run build`), then stage fonts (see Fonts section below).
- `builds:` one entry:
  - `env: [CGO_ENABLED=0]`.
  - `goos: [linux]`.
  - `goarch: [amd64, arm64]`.
  - `ldflags`: inject Version and CommitSHA into `github.com/kozaktomas/photo-sorter/cmd` using goreleaser template vars (`-X .../cmd.Version={{.Version}} -X .../cmd.CommitSHA={{.ShortCommit}}`) plus `-s -w` for size. Match the symbol names already used in `Dockerfile`.
  - `main: .` (root `main.go`).
  - Binary name: `photo-sorter`.
- `archives:` keep a `tar.gz` archive for raw binary distribution (so users who don't want the deb can still grab a tarball).
- `nfpms:` one entry producing `deb` only (no rpm / apk / archlinux):
  - `vendor`, `homepage`, `maintainer`, `description`, `license: MIT` (verify against `LICENSE`).
  - `section: misc`, `priority: optional`.
  - `bindir: /usr/bin`.
  - `formats: [deb]`.
  - `file_name_template`: `'{{ .ProjectName }}_{{ .Version }}_{{ .Os }}_{{ .Arch }}'`.
  - `dependencies:` (the deb's `Depends:` field) — see Runtime Dependencies section.
  - `contents:` — see Contents section.
  - `scripts.postinstall`, `scripts.preremove`, `scripts.postremove` — see Maintainer Scripts section.
- `changelog:` sort ascending, exclude `^docs:` and `^test:` commits (mirror teltonika-exporter).
- `release.footer`: "Released by GoReleaser" line is fine.

### 2. `deb/` directory at repo root

Create:

- `deb/photo-sorter.service` — systemd unit. Contents:
  ```
  [Unit]
  Description=Photo Sorter
  Documentation=https://github.com/kozaktomas/photo-sorter
  After=network.target

  [Service]
  User=photo-sorter
  Group=photo-sorter
  EnvironmentFile=/etc/photo-sorter/photo-sorter.env
  ExecStart=/usr/bin/photo-sorter serve
  ExecReload=/usr/bin/env kill -HUP $MAINPID
  Restart=always
  RestartSec=5s
  WorkingDirectory=/var/lib/photo-sorter
  TimeoutStopSec=30s

  [Install]
  WantedBy=multi-user.target
  ```

- `deb/photo-sorter.env` — sample env file shipped as a conffile. Include every env var documented in `CLAUDE.md` (database, AI providers, storage paths, web server, trash retention, duplicate detection, embeddings, etc.). All lines commented out (`# DATABASE_URL=postgres://...`) except for sensible production defaults like:
  ```
  WEB_HOST=0.0.0.0
  WEB_PORT=8080
  STORAGE_ORIGINALS_PATH=/var/lib/photo-sorter/originals
  STORAGE_CACHE_PATH=/var/lib/photo-sorter/cache
  ```
  Add comment headers grouping vars by purpose (Database / AI Providers / Storage / Web / Embeddings / Duplicate Detection / Trash / MCP). At the top of the file, a banner pointing to `https://github.com/kozaktomas/photo-sorter/blob/main/CLAUDE.md` for the authoritative list and a sentence about Bookman Old Style not being included (link to the proprietary-font note in the README).

- `deb/postinstall.sh`:
  ```sh
  #!/bin/sh
  set -e

  groupadd --system photo-sorter || true
  useradd --system -d /var/lib/photo-sorter -s /usr/sbin/nologin -g photo-sorter photo-sorter || true

  chown root:photo-sorter /etc/photo-sorter/photo-sorter.env
  chmod 640 /etc/photo-sorter/photo-sorter.env

  mkdir -p /var/lib/photo-sorter/originals /var/lib/photo-sorter/cache
  chown -R photo-sorter:photo-sorter /var/lib/photo-sorter

  fc-cache -f >/dev/null || true

  systemctl daemon-reload
  systemctl enable photo-sorter || true

  cat <<'EOF'

  ─────────────────────────────────────────────────────────────
   photo-sorter installed.

   Next steps:
     1. Edit /etc/photo-sorter/photo-sorter.env and set at minimum:
          - DATABASE_URL
          - WEB_SESSION_SECRET
     2. Start the service:
          sudo systemctl start photo-sorter
     3. Browse to http://<host>:8080
  ─────────────────────────────────────────────────────────────

  EOF
  ```
  Do NOT run `systemctl start photo-sorter` here. The service will fail without DATABASE_URL set, polluting the journal on first install. The printed instructions tell the operator what to do.

- `deb/preremove.sh`:
  ```sh
  #!/bin/sh
  set -e
  if [ "$1" != "remove" ] && [ "$1" != "purge" ]; then
    exit 0
  fi
  systemctl disable photo-sorter || true
  systemctl stop photo-sorter    || true
  ```

- `deb/postremove.sh`:
  ```sh
  #!/bin/sh
  set -e
  systemctl daemon-reload || true
  if [ "$1" = "purge" ]; then
    # Remove regenerable state on purge, but never originals (user data).
    rm -rf /var/lib/photo-sorter/cache
    rm -rf /etc/photo-sorter
    userdel  photo-sorter 2>/dev/null || true
    groupdel photo-sorter 2>/dev/null || true
    echo "Note: /var/lib/photo-sorter/originals/ was preserved. Remove manually if no longer needed."
  fi
  ```
  Make all three scripts executable in the repo (`chmod +x deb/*.sh`).

### 3. Contents (nfpms.contents)

In `.goreleaser.yaml`, declare:
```yaml
contents:
  - src: deb/photo-sorter.service
    dst: /lib/systemd/system/photo-sorter.service
  - src: deb/photo-sorter.env
    dst: /etc/photo-sorter/photo-sorter.env
    type: config|noreplace
  - src: dist/fonts/*
    dst: /usr/local/share/fonts/photo-sorter
    file_info:
      mode: 0644
```
The `dist/fonts/` directory is created by the font-staging step (see Fonts section). Use `type: config|noreplace` so dpkg treats the env file as a conffile and does not overwrite operator edits on upgrade.

### 4. Runtime dependencies (nfpms.dependencies)

Set the deb's `Depends:` field to:
- `libimage-exiftool-perl` (XMP sidecar writes via the `exiftool` subprocess in `internal/web/handlers/photos.go` EXIF edit endpoint)
- `texlive-luatex`, `texlive-latex-recommended`, `texlive-fonts-recommended`, `texlive-lang-czechslovak`, `texlive-pictures` (lualatex + Czech hyphenation patterns for `internal/latex/`)
- `texlive-latex-extra` (provides `enumitem.sty`; the Dockerfile fetches that single file from CTAN to avoid `texlive-latex-extra`, but on a server, just pulling the bigger package is simpler)
- `fontconfig` (for `fc-cache` in postinstall and at runtime)
- `libheif-examples` (provides `heif-convert` for HEIC/HEIF uploads — confirm the package name on Ubuntu 24.04; on older Debian it may be `libheif-examples`, on some distros `libheif-bin`. If the name differs across Ubuntu LTS versions, alternative-or syntax `libheif-examples | libheif-bin` is supported by nfpm.)
- `dcraw` (RAW upload pipeline: CR2/NEF/ARW/DNG)
- `postgresql-client` (for the `db-export` / `db-import` CLI; these wrap `pg_dump` / `pg_restore`)
- `ca-certificates`

Use the nfpm `dependencies:` list verbatim — that translates directly to Debian `Depends:`.

### 5. Fonts staging

Add a goreleaser `before.hook` that produces `dist/fonts/` before nfpms runs:
```yaml
before:
  hooks:
    - go mod tidy
    - sh -c "cd web && npm ci && npm run build"
    - sh -c "mkdir -p dist/fonts && scripts/install-fonts.sh dist/fonts"
```
- Verify the `scripts/install-fonts.sh` script accepts a target directory argument. If it currently hardcodes a path or requires sudo, modify it to support `install-fonts.sh <dest-dir>` without sudo when `<dest-dir>` is writable. Keep the existing `make install-fonts` behaviour working.
- The font set must match what `Dockerfile` ships today (24 free fonts, no Bookman Old Style). If the script downloads fonts at build time, the workflow needs internet (GitHub Actions runners have that).
- Add a `.gitignore` rule for `dist/` if not already present.

### 6. GitHub Actions: `.github/workflows/release.yml`

```yaml
name: Release

on:
  push:
    tags: ['v*.*.*']

permissions:
  contents: write   # for goreleaser to create the GitHub Release

jobs:
  release:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
        with: { fetch-depth: 0 }

      - uses: actions/setup-go@v5
        with: { go-version: '1.26' }   # match go.mod

      - uses: actions/setup-node@v4
        with: { node-version: '22' }   # match Dockerfile

      - name: Install font-staging dependencies
        run: sudo apt-get update && sudo apt-get install -y curl unzip fonts-conf

      - uses: goreleaser/goreleaser-action@v6
        with:
          distribution: goreleaser
          version: latest
          args: release --clean
        env:
          GITHUB_TOKEN: ${{ secrets.GITHUB_TOKEN }}
```

Notes for the implementing agent:
- Confirm the Go and Node versions against the current `go.mod` / Dockerfile before committing — the spec lists known values but they may have moved.
- Cross-compilation to `arm64` from an `ubuntu-latest` x86_64 runner is fine because the binary is pure Go (`CGO_ENABLED=0`). No QEMU setup needed.
- Do NOT add a docker-build step here; that lives in the existing `docker-publish.yml` and triggers on the same tag.

## Edge Cases

- **Versioning**: tags must be `v<MAJOR>.<MINOR>.<PATCH>` for goreleaser's semver matching. Snapshot builds (no tag) get a derived dev version. Ensure the `Version` ldflag still resolves to a useful string for snapshot builds.
- **Conffile semantics**: the env file uses `type: config|noreplace`. Adding new env vars in future releases will NOT update existing operator copies. Document this in the env file header: "After upgrading photo-sorter, diff against `/etc/photo-sorter/photo-sorter.env.dpkg-dist` for any new options."
- **Originals on purge**: postremove never deletes `/var/lib/photo-sorter/originals/`. This is intentional — operator data, never auto-delete.
- **Font cache**: `fc-cache -f` can take a minute on slow hardware. Run synchronously in postinstall so lualatex sees the fonts on first run.
- **Bookman Old Style**: not bundled. Document in README the manual install path (download from publisher, drop into `/usr/local/share/fonts/photo-sorter/`, `fc-cache -f`). Photo book PDF export still works without it; only certain typography presets degrade.
- **Existing Dockerfile and docker-publish workflow**: keep both intact. The deb is an additional distribution channel, not a replacement.
- **Bookman / proprietary fonts in `latex.ValidateFont`**: the Go code may reject font names that are not on the system. If Bookman is in the registry but not installed, that's the operator's problem; the existing validation handles it.

## Verification

- `goreleaser check` against the committed config passes.
- `goreleaser release --snapshot --clean --skip=publish` on the build machine (`ssh box@box`, faster than the Pi) produces:
  - `dist/photo-sorter_*_linux_amd64.deb`
  - `dist/photo-sorter_*_linux_arm64.deb`
  - Matching `.tar.gz` archives.
- Install the amd64 deb into a clean Ubuntu 24.04 container:
  ```
  docker run --rm -it -v $(pwd)/dist:/in ubuntu:24.04 bash -c '
    apt update && apt install -y /in/photo-sorter_*_linux_amd64.deb &&
    dpkg -L photo-sorter &&
    systemctl status photo-sorter || true &&
    /usr/bin/photo-sorter --help'
  ```
  - `dpkg -L photo-sorter` must list the binary, the service, the env file, and the fonts.
  - `photo-sorter --help` must run.
  - All declared deps must install cleanly (no missing-package errors).
- Tag a test release (`git tag v0.0.1-rc1 && git push --tags`) on a feature branch and confirm:
  - The `release.yml` workflow runs to completion.
  - A draft / pre-release is created on GitHub with both .deb files attached.
- Roll back the test tag after verification (`git tag -d v0.0.1-rc1 && git push --delete origin v0.0.1-rc1`).
