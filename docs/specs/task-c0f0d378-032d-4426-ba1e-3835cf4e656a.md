# Migration verification + diff report

A CLI command that compares an existing PhotoPrism instance to the photo-sorter database to confirm the one-shot migration moved everything correctly. Runs read-only against both, produces a printable report (and optional JSON output) listing any missing rows.

## Requirements

### Command

```bash
go run . migrate-verify \
  --pp-db "photoprism:...@tcp(...)/photoprism" \
  --pp-originals /photoprism/originals \
  [--json]
```

Add `cmd/migrate_verify.go`.

### Checks

For each section, print COUNTS first, then the first 50 missing items per category.

1. **Photos**
   - PhotoPrism row count vs sorter `photos` count (matching by SHA256 of the primary file).
   - For each PP photo, recompute the SHA256 of the source file and verify a `photos` row exists with `file_hash = X`.
   - Photos found only in PP (missed by migration) → "missing_in_sorter".
   - Photos found only in sorter without a corresponding PP file → "orphan_in_sorter".

2. **Albums**
   - Slug + title match.
   - Photo-set difference per album (PP album has X photos, sorter album has Y; report the symmetric diff).

3. **Labels**
   - Slug + name match.
   - Photo-label pair counts.

4. **Subjects + markers**
   - Subject name match (accent-insensitive).
   - Marker counts per subject.
   - Markers where the geometry differs by more than 1% on any of x/y/w/h.

5. **Files on disk**
   - Walk the sorter originals directory and compare against the photos `file_path` column → orphan files report.

### Output

Default human-readable (sectioned, color-coded if `--no-color` is not set). `--json` emits a structured report:

```json
{
  "photos": { "pp_count": 0, "sorter_count": 0, "missing_in_sorter": [...], "orphan_in_sorter": [...] },
  "albums": { ... },
  "labels": { ... },
  "subjects": { ... },
  "markers": { ... },
  "disk": { ... }
}
```

### Performance

- For SHA256, recompute only when the size matches (size mismatch already means non-identical). Cache via memoizing on the file path.
- Walk in parallel with a goroutine pool — concurrency 4.

### Tests

A small integration test feeding a tiny PP MariaDB + originals dir into a sorter Postgres testcontainer, then running verify. Expect zero diffs after migration; introduce a manual diff (delete a photo in sorter) and expect it to be reported.

## Verification

- `make test` passes.
- `make lint`, `make build-go` pass.
