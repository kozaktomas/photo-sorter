# Auth refactor: native login + role-aware session middleware

Replace the PhotoPrism-credential-based login in `internal/web/handlers/auth.go` with a native flow that authenticates against the local `users` table and exposes the user's role in the request context for downstream handlers.

This task assumes the `users` table, `UserReader`/`UserWriter`, and `internal/auth` package already exist.

## Requirements

### Files

- `internal/web/handlers/auth.go` — rewrite.
- `internal/web/handlers/auth_test.go` — update.
- `internal/web/middleware/` — session middleware (modify existing or create file `auth_context.go`).
- `internal/database/postgres/sessions.go` — extend the session row to store the user's role so the middleware can avoid an extra DB hit per request.
- Migration `033_add_session_role.sql`: add `role VARCHAR(16) NOT NULL DEFAULT 'viewer'` to `sessions`.

### Login flow

`POST /api/v1/auth/login`:

Request: `{ "username": "...", "password": "..." }`.

Steps:
1. Lookup `UserReader.GetUserByUsername`. On miss or `Disabled` true, return 401 with a generic message.
2. `auth.CheckPassword(plain, hash)` → on mismatch return 401.
3. Create a new session row containing the user's `uid`, `role`, a generated `token`, and a `download_token`. Persist via the existing session store. Expiry: 30 days.
4. `UserWriter.TouchLastLogin(uid)` — fire-and-forget in a goroutine (ignore errors).
5. Set the HttpOnly session cookie (existing helper).
6. Return `{ user: { uid, username, display_name, role } }`.

### Logout

`POST /api/v1/auth/logout` — unchanged contract but make sure the session row is hard-deleted (not soft-deleted).

### Auth status

`GET /api/v1/auth/status`:
- If a valid session cookie is present, return `{ authenticated: true, user: { uid, username, display_name, role } }`.
- Otherwise `{ authenticated: false }`.

### Middleware

Replace the existing session-loading middleware so that on a valid session it injects an `*AuthInfo` into the context:

```go
type AuthInfo struct {
    UserUID  string
    Username string
    Role     string
}

func GetAuthInfo(ctx context.Context) (*AuthInfo, bool)
func MustGetAuthInfo(ctx context.Context, w http.ResponseWriter) *AuthInfo  // writes 401 + returns nil if missing
```

Add a role-gating wrapper:

```go
func RequireRole(roles ...string) func(http.Handler) http.Handler
```

Used like `r.With(middleware.RequireRole(auth.RoleAdmin)).Post(...)`.

### PhotoPrism client decoupling

The handlers in `albums.go`, `labels.go`, `photos.go` no longer go through PhotoPrism for these endpoints. The existing `middleware.MustGetPhotoPrism` helper continues to exist for the face/upload-to-PhotoPrism code paths (faces refactor is a later task). For this task, just make sure `MustGetPhotoPrism` does NOT call any PhotoPrism login when the session has a non-empty `user_uid` and the route is one of the already-native endpoints.

### Env vars to remove (preparation only)

This task does NOT delete `PHOTOPRISM_USERNAME` / `PHOTOPRISM_PASSWORD` — the upload + face paths still use them. Final cleanup is in the photoprism-package-removal task.

### Tests

- Login with valid credentials returns 200, cookie set, user payload includes `role`.
- Login with wrong password → 401.
- Disabled user → 401.
- Status returns the user after login.
- `RequireRole(RoleAdmin)` blocks editors and viewers with 403.
