# Audit Log

Add a server-side audit log that records every authenticated mutating action with who/what/when/where, plus an admin-only viewer in the web UI.

## Database

- Add migration `042_audit_log.sql`:
  - Table `audit_log`:
    - `id BIGSERIAL PRIMARY KEY`
    - `user_uid TEXT NULL REFERENCES users(user_uid) ON DELETE SET NULL` (NULL for anonymous events like `login_failed`)
    - `action TEXT NOT NULL` (see enum below)
    - `entity_type TEXT NULL` (`photo`, `album`, `label`, `subject`, `user`, `book`, `share_link`, `smart_album`, `session`)
    - `entity_uid TEXT NULL` (the UID of the affected entity, when applicable)
    - `metadata JSONB NOT NULL DEFAULT '{}'` (action-specific extras: e.g. `{ "count": 42 }` for batch ops)
    - `ip TEXT NULL`
    - `user_agent TEXT NULL`
    - `created_at TIMESTAMP NOT NULL DEFAULT NOW()`
  - Indexes: `(user_uid, created_at DESC)`, `(action, created_at DESC)`, `(entity_type, entity_uid)`, `(created_at DESC)`.

## Actions to Track

- **auth**: `login`, `logout`, `login_failed`, `password_change`
- **photo**: `photo_upload`, `photo_update`, `photo_exif_edit`, `photo_archive`, `photo_restore`, `photo_purge`, `photo_batch_edit`, `photo_batch_label`
- **album**: `album_create`, `album_update`, `album_delete`, `album_photos_add`, `album_photos_remove`
- **label**: `label_update`, `label_delete`
- **subject**: `subject_update`
- **face**: `face_apply` (with action: create_marker / assign_person / unassign), `face_outlier_unassign`
- **user**: `user_create`, `user_update`, `user_disable`, `user_enable`, `user_delete`, `user_password_reset`
- **book**: `book_create`, `book_update`, `book_delete`, `book_export_pdf`
- **share_link**: `share_link_create`, `share_link_revoke`, `share_link_password_verify`, `share_link_password_failed`
- **smart_album**: `smart_album_create`, `smart_album_update`, `smart_album_delete`
- **process**: `process_job_start`, `process_job_cancel`, `sort_job_start`, `sort_job_cancel`

Do NOT log read-only actions (GET endpoints). The point is to track mutations and security-sensitive events.

## Implementation Notes

- Add `internal/audit/` package with `Logger` type that wraps the database writer. Expose `Logger.Log(ctx, action, entityType, entityUID, metadata)`. The user_uid, IP, and user_agent are pulled from request context inside `Log()` — handlers just pass the action + entity info.
- Add a Chi middleware (`internal/web/middleware/audit.go`) that injects the audit logger into the request context. Handlers retrieve it via a context key helper.
- Wire `Logger.Log` calls into existing handlers at the point AFTER the mutation succeeds (don't log failed operations except for `login_failed` and `share_link_password_failed` which are explicit security events).
- For batch operations, log a single row with `metadata.count`, not one row per item.
- Failures to write the audit log must NOT fail the underlying request — log them at WARN level and continue.

## Endpoints

- `GET /api/v1/audit-log` (admin only):
  - Query params: `user_uid`, `action`, `entity_type`, `entity_uid`, `since` (ISO8601), `until` (ISO8601), `limit` (default 50, max 200), `offset`.
  - Response: `{ entries: [...], total: number, limit, offset }`.
  - Each entry includes the joined `user_username` (best-effort — NULL if user was deleted).

## Frontend

- New page `/settings/audit-log` (admin only; non-admins get 403/redirected).
- Filter bar: user combobox (loaded from `/api/v1/users`), action dropdown (grouped by category), entity type dropdown, date range pickers.
- Table columns: timestamp (local time), user, action (with friendly label), entity (type + clickable UID linking to the entity's page when feasible), IP, metadata (JSON pretty-print, collapsed by default).
- Pagination with limit selector (50/100/200).
- Export current view as CSV button.

## i18n

- Czech + English strings under `auditLog` namespace in `web/src/i18n/locales/{cs,en}/pages.json`. Map each `action` to a human-readable label.

## Edge Cases

- Deleted user: `user_uid` becomes NULL (via ON DELETE SET NULL) — the join shows `<deleted user>`.
- Very high write volume during bulk uploads: log per-job-start + per-job-summary, not per-photo. Same for face processing.
- Retention: no auto-purge for v1. Document that the table grows unbounded — a future task can add retention.
