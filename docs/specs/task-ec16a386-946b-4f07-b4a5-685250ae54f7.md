# Robustness sweep: background jobs, SSE, daemons

Audit every background job manager and SSE handler. Find leaked goroutines, missed cancellations, deadlocks, channel-write-after-close panics, and orphaned subprocesses. Fix what is unambiguous.

## Scope (files in focus)

- `internal/web/handlers/sse.go` (shared SSE plumbing).
- Sort job manager (`internal/web/handlers/sort.go` + helpers).
- Upload job manager (`internal/web/handlers/upload_job.go`, `internal/web/handlers/upload.go`).
- Process job manager (`internal/web/handlers/process.go`) and its build-thumbs piggyback.
- Book export job manager (`internal/web/handlers/book_export_job.go`) with the lualatex subprocess.
- The hourly trash auto-purge daemon (look in `cmd/serve.go` for the spawn site).
- `internal/trash/` for the purge implementation.
- `internal/latex/latex.go` for the lualatex subprocess + the `ExportOptions.OnProgress` callback wiring.

Out of scope: file IO safety inside the purge / upload paths (separate sweep).

## What to look for

1. **SSE client disconnect**
   - When the browser closes the SSE stream mid-job, the server-side handler must detect the disconnect (via `Request.Context().Done()`) and stop writing — otherwise the goroutine leaks for the whole job duration.
   - Detection must NOT cancel the underlying job (the job runs to completion in the background even if the client navigated away — confirm this is the documented behavior; if not, decide and document).
   - Multiple SSE subscribers per job (re-connect, second tab) — confirm the manager supports it or rejects cleanly.

2. **Job cancellation propagation**
   - `DELETE /api/v1/sort/{jobId}`, `/upload/{jobId}`, `/process/{jobId}`, `/book-export/{jobId}` must propagate cancellation to the worker context so in-flight HTTP calls (AI providers, embeddings, downloads) abort promptly.
   - For book export: cancellation must SIGKILL the lualatex subprocess (documented). Verify the kill actually fires and the temp file is removed.
   - Two cancels in quick succession do not panic.

3. **Channel + goroutine hygiene**
   - No `close()` on a channel while another goroutine may still write to it (panic risk).
   - Workers always exit via `select { case <-ctx.Done(): }` or a sentinel — no infinite loops without cancellation.
   - `sync.WaitGroup.Add` is called before `go func()`, never inside the worker.
   - Mutex hold time does not span network or disk IO.

4. **Per-project / per-resource lock correctness**
   - The book export manager rejects a concurrent export for the same book with 409. Confirm the rejection check is inside the same lock as the insertion (no TOCTOU window).
   - The build-thumbs job piggybacks on `ProcessJobManager` — confirm only one of {embeddings job, build-thumbs job} runs at a time per the documented behavior.

5. **Job state across restart**
   - Jobs are in-memory only (no DB row). Confirm the server does not advertise a stale job ID to clients after restart, and does not panic on `GET /jobs/<old_id>/events` after restart (should be 404, not 500).
   - SSE clients reconnecting to a job that completed during their absence get a sensible response (final state or 404, never a hang).

6. **Daemon edge cases**
   - The hourly auto-purge daemon: panics in one iteration must not kill the loop (recover + log).
   - Daemon shuts down cleanly when the server context is cancelled (no goroutine leak on test re-runs).
   - The cutoff query uses `TRASH_RETENTION_DAYS` correctly — boundary photo (archived exactly at cutoff) is purged on the next tick, not skipped forever.

7. **Progress / event payloads**
   - SSE event types match `web/src/types/events.ts` (discriminated unions). A typo here breaks the UI silently.
   - `OnProgress` callback in `internal/latex/latex.go` is invoked under the worker goroutine, not the calling request goroutine — confirm no shared mutable state without a lock.

8. **Subprocess lifecycle**
   - `exiftool`, `heif-convert`, `dcraw`, `lualatex` subprocesses all have a context-bound `exec.CommandContext` so cancellation kills them.
   - stdout/stderr are bounded (no `io.ReadAll` on an attacker-controllable stream); errors are surfaced with a snippet, not silently swallowed.

## How to work

1. Spend the first pass building a list of every job manager and every `go func()` in the scope. Note which contexts they listen to.
2. For each confirmed bug: focused commit (`fix(jobs): ...`) with a short, accurate message.
3. For ambiguous cases (e.g. "should cancel-on-disconnect be the default?"): pick the safer default and document in `TODO.md` under `## Jobs / SSE hardening sweep — YYYY-MM-DD`.
4. Add tests for at least the high-confidence fixes — race conditions are tricky, but a `go test -race` over the manager package catches a lot.

## Verification

- `make lint` must pass.
- `make test` must pass (`make test` runs with `-race`).
- `make check` runs the full gate.

## Done when

- Every job manager + daemon in scope has been audited.
- Fixes committed, ambiguous items in `TODO.md`.
- Final report lists: managers audited, bugs fixed, deferred items, and any architectural concerns worth raising (e.g. "job state should be persisted across restarts").
