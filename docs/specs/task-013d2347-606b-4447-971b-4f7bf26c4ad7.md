# Refresh operator runbooks (migration, testing, backup)

Bring the three operator-facing runbooks in sync with current tooling:
- `docs/migration-from-photoprism.md` (one-shot import from PhotoPrism)
- `docs/testing-environment.md` (dev / test environment setup)
- `docs/backup.md` (backup + restore runbook)

## Scope

- Files to edit: `docs/migration-from-photoprism.md`, `docs/testing-environment.md`, `docs/backup.md`.
- Source of truth: `cmd/migrate.go` (or split migration files), `cmd/verify.go`, `cmd/backup.go`, `cmd/db_export.go`, `cmd/db_import.go`, `dev.sh`, `docker-compose.yml`, `Makefile`, `scripts/install-fonts.sh`, `.env.dev` (if present), `Dockerfile`.

## What to verify and update

### docs/migration-from-photoprism.md

1. Confirm the runbook describes the actual command set: `migrate-from-photoprism` (reads PhotoPrism's MariaDB + copies originals into the photo-sorter layout), `migrate-verify` (field-level diff with tolerance bands; `--strict` disables them), `migrate-remap-references` if still relevant.
2. State that UIDs are preserved verbatim across photos, albums, subjects, markers — cached references in `embeddings`, `faces`, `section_photos`, `page_slots` stay valid without a remap pass.
3. Document migrated fields explicitly: keywords, scan / panorama / quality flags, timezone, EXIF tags, subject bio, label description, album location / filter.
4. Document the "clean migrate-verify" gate before dropping PhotoPrism + MariaDB.
5. Confirm that `internal/photoprism/` is retained only to drive these migration commands; no runtime dependency on PhotoPrism remains.

### docs/testing-environment.md

1. Confirm the dev script (`./dev.sh`, `./dev.sh --force`) behavior: stop, npm install, frontend build, Go build, start on port 8085, smart caching.
2. Document the managed dev service: PostgreSQL with pgvector via `docker-compose.yml`; embeddings (CLIP + faces) is external and configured via `EMBEDDING_URL` in `.env.dev`.
3. Confirm originals tree default at `./data/originals` and cache at `./data/cache`.
4. External binaries the upload pipeline shells out to in dev: `exiftool`, `heif-convert` (libheif-tools), `dcraw` (LibRaw). For dev install via OS package manager; production reads them from the Docker image.
5. Book typography fonts — host-side install via `make install-fonts` (uses sudo, idempotent, installs to `/usr/local/share/fonts/photo-sorter` because the lualatex subprocess in `internal/latex/latex.go` overrides HOME and hides user-local font dirs). Bookman Old Style is proprietary.
6. Confirm test commands (`make test`, `make test-v`, single-test invocation pattern) match the Makefile.
7. Quality gate (`make check` = fmt + vet + lint + test). Pre-commit hook checks `make lint` for Go changes and `npx tsc --noEmit` + `npm run lint` for frontend changes.

### docs/backup.md

1. Document the operator runbook for backing up and restoring a photo-sorter install, end-to-end.
2. DB-side: `photo-sorter db-export -o <file>` produces a single pg_dump file. `photo-sorter db-import -i <file> --yes` restores it (matching `pg_restore`).
3. Originals side: archival is operator-driven — `rsync`, `borg`, or whatever fits. Describe the `YYYY/MM/<filename>` on-disk layout.
4. Combined: `photo-sorter backup` bundles both into a timestamped directory.
5. Restore on a new host: run `db-import`, restart the server, then `cache build-thumbs` to regenerate the thumbnail cache from the restored originals.
6. Make explicit that the thumbnail cache is intentionally not backed up (regenerable).
7. Cross-link to `docs/cli-reference.md` for full flag tables.

## Rules

- Code is the source of truth. Open `cmd/*.go`, `dev.sh`, and the Makefile before documenting.
- Do not invent commands, flags, paths, or behaviors. Grep before you write.
- Preserve the existing structure of each file; do surgical edits.
- Keep examples concrete and copy-pasteable. Use real paths and a single canonical environment style.

## Done when

- `migration-from-photoprism.md` matches the current CLI + verify gate + preserved fields.
- `testing-environment.md` matches `dev.sh`, `docker-compose.yml`, the Makefile, and the external binary requirements.
- `backup.md` documents the full `db-export` / `db-import` / `backup` flow plus originals + thumbnail-cache rebuild on restore.
- No mention of removed services (PhotoPrism / MariaDB dev container) or removed commands.
