# Refresh docs/API.md

`docs/API.md` is the full REST API reference (currently ~3 760 lines). Bring it in sync with the routes actually wired up in the server. This is the doc operators, integrators, and frontend devs use to understand the wire protocol.

## Scope

- File to edit: `docs/API.md` only.
- Source of truth: Chi route registrations in `internal/web/` (router setup file + handler packages under `internal/web/handlers/`). Cross-reference with the typed API client at `web/src/api/client.ts`.

## What to verify and update

1. **Route inventory** — enumerate every route registered on the router and confirm it appears in `docs/API.md`. Conversely, remove any documented endpoint that no longer exists.
2. **Auth model** — cookie-based sessions; role-based access (admin/editor/viewer); per-share `share_<slug>` cookie for public album shares; rate-limit on `share/{slug}/verify`. Confirm which roles can call which endpoints.
3. **Recently added endpoint families** — verify these are all documented with the correct request/response shape:
   - `/api/v1/me/*` and `/api/v1/users/*` (user management; admin-only mutations; last-admin guard).
   - `/api/v1/audit-log` (admin-only; filter params; envelope; FK SET NULL behavior).
   - `/api/v1/photos/{uid}/edits` (GET/PUT/DELETE for non-destructive edits; ranges; HEIC/RAW 503 path).
   - `/api/v1/photos/{uid}/download` (renders edits by default; `?original=true` bypass).
   - `/api/v1/photos/{uid}/exif` (XMP sidecar write; validation rules).
   - `/api/v1/photos/trash`, `/api/v1/photos/batch/restore`, `/api/v1/photos/batch/purge` (admin-only; auto-purge daemon).
   - `/api/v1/photos/batch/archive`, `/api/v1/photos/batch/edit`, `/api/v1/photos/batch/labels`.
   - `/api/v1/photos/search-by-text` (Czech → CLIP translate) and `/api/v1/photos/duplicates`.
   - `/api/v1/smart-albums*` (saved filters; immutable UID; per-call recompute).
   - `/api/v1/albums/{uid}/share`, `/api/v1/albums/{uid}/shares`, `/api/v1/shares/{slug}` (mint / list / revoke).
   - `/api/v1/public/share/{slug}/*` (no auth; verify; photos; thumbs; download with Range).
   - `/api/v1/process/build-thumbs` (admin-only; SSE; reuses ProcessJobManager).
   - `/api/v1/upload/job` and `/api/v1/upload/{jobId}/events` (SSE pipeline).
   - `/api/v1/books/*` full surface, including `update_book` typography payload, page `hide_page_number`, captions slot, contents slot, slot swap, auto-layout, preflight (with `photo_quality`), and the export job flow.
   - `/api/v1/text/*` (check / check-and-save / rewrite / consistency; 3-tier cache).
   - `/api/v1/text-versions*`.
4. **Query parameters** — verify documented filter / sort / pagination params match what handlers actually parse. Example: `GET /api/v1/photos` filters (`album_uid`, `label_uid`, `subject_uid`, `favorite`, `private`, `archived`, `taken_from`, `taken_to`, bbox lat/lng, `q`, `sort`, `limit`, `offset`).
5. **Response envelopes** — confirm envelopes match what handlers write (e.g. `{ photos, total, limit, offset }`, `{ entries, total, limit, offset }`, `{ edits: ...|null }`).
6. **Status codes** — verify documented errors match what handlers return (404 for archived photos without `?include_archived=true`, 409 for concurrent book export jobs, 410 for expired share links, 429 + Retry-After on share verify rate limit, 503 for missing HEIC/RAW decoders, etc.).
7. **SSE event schemas** — for sort, upload, process, build-thumbs, and book export, confirm event names + payloads match `internal/web/handlers/sse.go` and event types in `web/src/types/events.ts`.
8. **Examples** — every `curl` example must use a real endpoint and a current request shape.

## Rules

- Code is the source of truth. Read the handler before documenting the behavior. Do not infer.
- Do not invent endpoints, query params, fields, or status codes. Grep before you write.
- Keep the existing structure (per-resource sections). Prefer surgical edits over rewrites.
- Use the same envelope conventions throughout (do not mix styles).
- If an endpoint has tricky semantics (audit log, share verify rate limit, photo download render-vs-original, last-admin guard), call it out explicitly.

## Done when

- Every route wired in `internal/web/` is documented in `docs/API.md`.
- No documented endpoint is missing from the server.
- Recently added endpoint families (above) are fully documented with realistic request / response shapes.
- Query params, response envelopes, and error codes match handler behavior at the current commit.
