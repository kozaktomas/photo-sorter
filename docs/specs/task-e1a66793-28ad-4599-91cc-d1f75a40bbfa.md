# Public Album Share Links

Allow album owners to share an album via a public URL. Recipients do not need an account. Links can optionally be password-protected and/or have an expiration date.

## Requirements

- Each share link has:
  - A `slug` that forms the URL (`/share/<slug>`). The slug is auto-generated from the album title (unaccent + lowercase + dashes for spaces — similar pattern to `facematch.NormalizePersonName`). If the slug already exists, append `-2`, `-3`, etc. The creator can override the slug to any string matching `^[a-z0-9-]{3,64}$` (reject other values).
  - Optional `password` — bcrypt-hashed in DB; the bare password is never persisted.
  - Optional `expires_at` — NULL means no expiration.
  - `created_at`, `created_by_user_uid`.

## Database

- Add migration `039_album_share_links.sql`:
  - Table `album_share_links` with columns: `slug TEXT PRIMARY KEY`, `album_uid TEXT NOT NULL REFERENCES albums(album_uid) ON DELETE CASCADE`, `password_hash TEXT NULL`, `expires_at TIMESTAMP NULL`, `created_at TIMESTAMP NOT NULL DEFAULT NOW()`, `created_by_user_uid TEXT NOT NULL REFERENCES users(user_uid)`.
  - Index on `album_uid` for the "list links for album" query.

## Authenticated Endpoints (HasWriteAccess required)

- `POST /api/v1/albums/{uid}/share` — create link. Body: `{ slug?: string, password?: string, expires_at?: ISO8601 }`. Returns the full link record (without password_hash; include `has_password: bool`).
- `GET /api/v1/albums/{uid}/shares` — list active links for the album. Never return `password_hash`; include `has_password: bool`.
- `DELETE /api/v1/shares/{slug}` — revoke a link.

## Public Endpoints (no session required)

These live under `/api/v1/public/share/{slug}/...` to clearly separate them from the authenticated API. They MUST NOT require a session cookie.

- `GET /api/v1/public/share/{slug}` — returns `{ has_password: bool, expires_at: ISO8601 | null, album: { title, photo_count, cover_thumb_url } }` if valid. Returns 404 if not found, 410 if expired. If `has_password` is true and the request lacks a valid share cookie, ONLY `{ has_password: true, expires_at }` is returned (album metadata stays hidden).
- `POST /api/v1/public/share/{slug}/verify` — body `{ password: string }`. On success, sets a `share_<slug>` HttpOnly short-lived cookie (24h) so subsequent requests for this share don't re-prompt. Returns `{ ok: true }`. Rate limit: max 10 attempts per IP per 5 minutes (in-memory map is fine).
- `GET /api/v1/public/share/{slug}/photos` — list photos in the album, paginated. Requires the share cookie if password-protected.
- `GET /api/v1/public/share/{slug}/photos/{photo_uid}/thumb/{size}` — public thumbnail (stream from cache, no auth check beyond share validity + photo membership in the album).
- `GET /api/v1/public/share/{slug}/photos/{photo_uid}/download` — stream the original primary file as attachment. Same Range-support behavior as the authenticated download.

All public endpoints must:
- Check the link is not expired before serving (return 410 if it is).
- Verify the photo actually belongs to the linked album (don't trust client-provided photo_uid blindly).
- Not return any user-identifying information.

## Frontend (Authenticated Side)

- On the album detail page, add a "Share" button. Opens a modal:
  - List of existing share links (slug, has_password badge, expires_at, copy-URL button, revoke button).
  - "Create new link" form: slug field pre-filled with auto-slug (editable), password field (optional), expiration date picker (optional — "Never" by default).
  - Show the full URL (`{window.location.origin}/share/<slug>`) with a copy button.

## Frontend (Public Viewer)

- Route `/share/:slug` is publicly accessible — must NOT redirect to login.
- Loads the public metadata endpoint. If password-protected and not yet verified, render a clean centered password gate (no app chrome).
- After verification (or for unprotected links), render a simplified gallery page: album title, photo grid (reuse `PhotoGrid` in a "public" mode that hides edit affordances), click a photo for a lightbox with a download button.
- No app navigation, no "Sign up" CTA in the chrome — the recipient came for the photos.
- Expired link: friendly page "This link expired on <date>". HTTP 410.

## Edge Cases

- Slug collision on auto-generate: append `-2`, `-3` etc.
- Album deleted: cascade deletes share links (foreign key).
- Single-photo download in the public viewer — yes, allowed. Bulk zip download is out of scope.
- Password rate-limit exceeded: 429 with `Retry-After`.
