# Thumbnail backfill background job

A CLI command + REST endpoint that walks all photos in the DB and generates any missing thumbnails. Used after migration, after a cache wipe, or whenever new size definitions are added.

## Requirements

### CLI

```bash
go run . cache build-thumbs [--concurrency 4] [--sizes fit_720,fit_1280,...] [--limit N] [--only-missing] [--photo-uid p123]
```

Add `cmd/cache_build_thumbs.go`.

Behaviour:
- Default: every photo, every size in the registry, only missing thumbs.
- `--photo-uid` regenerates one photo's thumbs (all sizes).
- `--sizes` overrides the size set (CSV).
- Progress bar with ETA.

For each photo:
- Resolve original path via storage.
- Call `imgconvert.EnsureDecodable` (HEIC/RAW → temp JPEG).
- Call `thumb.GenerateAll` with the requested sizes.
- Defer cleanup of any temp file.

### REST endpoint

`POST /api/v1/process/build-thumbs` — admin only. Body: `{ concurrency?, sizes?, only_missing? }`. Returns `{ job_id }`. SSE stream at `/api/v1/process/{jobId}/events` re-uses the existing process job machinery and emits `progress` events with `{ done, total, current_photo_uid }`.

### Job manager

Reuse the existing `process` job manager (`internal/web/handlers/process.go`) — extend its job kinds with `"build_thumbs"`. The job state and SSE pattern are already in place.

### Failures

- If decode fails for a single photo, log it, increment a `failed` counter, continue.
- After the job completes, emit a final `summary` event with `{ generated, skipped, failed }`.

### Tests

- Seed 3 photos, run the CLI with `--only-missing` → all thumbs present afterward.
- Re-run → no new files written.
- Single-photo regen works.

## Verification

- `make test` passes.
- `make lint`, `make build-go` pass.
