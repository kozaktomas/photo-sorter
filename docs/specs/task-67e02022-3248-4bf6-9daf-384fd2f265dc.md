# EXIF extraction

Create `internal/exif` — a package that extracts EXIF metadata from any uploaded photo (JPEG, PNG, HEIC, RAW formats) by invoking the system `exiftool` binary with `-json` output, plus a tiny pure-Go fallback for plain JPEG when `exiftool` is unavailable.

This task is independent of storage and DB — it operates on a file path or `io.Reader`.

## Requirements

### Package layout

```
internal/exif/
  exif.go         // public API
  exiftool.go     // subprocess invocation
  parse.go        // map exiftool JSON → typed struct
  exif_test.go
  testdata/       // small sample files (already-licensed or self-shot)
```

### Public API

```go
type Metadata struct {
    TakenAt        time.Time      // zero if unknown
    TakenAtSource  string         // "exif" / "filename" / "unknown"
    Width          int
    Height         int
    Orientation    int            // 1-8, default 1
    Mime           string         // e.g. "image/jpeg"
    Lat, Lng       *float64       // nil if absent
    Altitude       *float64
    CameraMake     string
    CameraModel    string
    LensModel      string
    ISO            *int
    Aperture       *float64       // f-number
    Exposure       string         // "1/250"
    FocalLength    *float64       // mm
    Raw            map[string]any // raw exiftool JSON for storing in jsonb
}

func Extract(ctx context.Context, path string) (*Metadata, error)
func ExtractFromReader(ctx context.Context, r io.Reader, filename string) (*Metadata, error)
```

`ExtractFromReader` should buffer to a temp file (cleaned up via `defer`) so it can call exiftool, since exiftool needs a file path.

### exiftool subprocess

- Command: `exiftool -json -n -fast2 -api LargeFileSupport=1 <file>`
  (`-n` returns numeric values rather than formatted strings; `-fast2` skips some slow tags but keeps EXIF/GPS.)
- 20-second timeout via `exec.CommandContext`.
- Parse the first object of the returned JSON array.
- On non-zero exit, fall back to the pure-Go parser if the file is a JPEG (magic-byte check).
- If `exiftool` binary is missing from PATH, log a warning ONCE (use `sync.Once`) and rely on the JPEG fallback. For non-JPEG files in this case, return a `Metadata` with only `Mime` filled and `TakenAtSource = "unknown"`.

### Pure-Go fallback

Use `github.com/rwcarlsen/goexif/exif` (or `github.com/dsoprea/go-exif/v3` — pick one; add to `go.mod`). Only used for JPEG, only fills the basic fields (TakenAt, Width/Height via image config decode, Orientation, GPS, camera, ISO, exposure).

### Filename date heuristic

If EXIF has no `DateTimeOriginal`, try parsing the filename for common patterns:
- `IMG_YYYYMMDD_HHMMSS.*`
- `YYYY-MM-DD HH.MM.SS.*`
- `PXL_YYYYMMDD_HHMMSS*.*` (Pixel)
- `Screenshot YYYY-MM-DD at HH.MM.SS.*`

If matched, set `TakenAt` and `TakenAtSource = "filename"`. Otherwise `TakenAtSource = "unknown"`.

### Tests

- Test against 3-4 small sample files in `testdata/`: a plain JPEG with full EXIF, an iPhone HEIC (skip if exiftool missing), and a JPEG with GPS.
- Test the filename heuristic with several patterns.
- Test that `Extract` returns sensible zero values on a malformed file (no panic).
- Tests that depend on the `exiftool` binary should `t.Skip` when `exec.LookPath("exiftool")` fails so CI without the binary still passes.

## Implementation Notes

- `exiftool` is added to the Docker image in a later task — do not modify `Dockerfile` here.
- Keep this package free of any DB / HTTP / storage dependencies.

## Verification

- `make test` passes.
- `make lint` and `make build-go` pass.
- `go test ./internal/exif/` works on a machine without `exiftool` installed (tests skip gracefully).
