# Drag-and-drop reorder for chapters, sections, and pages in BookEditor

Replace button-based reordering in the book editor with native drag-and-drop.

## Requirements

- Chapter list in BookEditor: each chapter row is draggable; dropping reorders within the book. Calls existing `PUT /api/v1/books/{id}/chapters/reorder`.
- Section list (in `SectionSidebar`): drag-reorder within the book. Calls `PUT /api/v1/books/{id}/sections/reorder`. A section may also be dropped onto a chapter row to set its `chapter_id` (calls `PUT /api/v1/sections/{id}` with new `chapter_id`).
- Page list (in `PageSidebar` / `PageMinimap`): drag-reorder within the book. Calls `PUT /api/v1/books/{id}/pages/reorder`. Dropping a page onto a different section row reassigns the page (calls `PUT /api/v1/pages/{id}` with new `section_id` — same path the MCP cross-section move uses).
- Visual feedback: dragged item dims to 50% opacity, drop targets get a highlighted insertion line, invalid drops show a red cursor / no-drop affordance.
- Optimistic update: reorder client-side immediately; on API error roll back to the prior order and show an error toast.
- Keep the existing keyboard nav (`useBookKeyboardNav`) working — it should not regress.
- Touch devices: drag should work via long-press; if that proves messy, fall back to the existing button-based reorder buttons (keep them).

## Implementation Notes

- Use `@dnd-kit/core` + `@dnd-kit/sortable` — it's accessible, lightweight, and supports the cross-list drop semantics (section → chapter, page → section) we need.
- Wrap each list in its own `SortableContext`; cross-list drops handled by checking `over.id` type at drop time.
