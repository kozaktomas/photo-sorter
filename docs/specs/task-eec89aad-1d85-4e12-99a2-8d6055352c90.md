# Native photo upload pipeline

Create `internal/photopipe` — orchestrates ingestion of a single uploaded photo from start to finish, using the new native building blocks (storage, exif, thumb, imgconvert, photos repo). PhotoPrism is not called.

This task does NOT yet wire the HTTP handler (that's the next task). It exposes a pure Go API that takes a reader + filename and returns the created `database.Photo`.

## Requirements

### Files

```
internal/photopipe/
  pipeline.go        // public API
  pipeline_test.go
```

### Public API

```go
type Options struct {
    Filename     string    // original filename from the upload
    UploadedBy   string    // user UID
    GenerateThumbs bool    // default true; can be false for migration use
    SkipDuplicates bool    // default true; if a photo with the same hash exists, return ErrDuplicate with the existing photo
}

type Pipeline struct {
    store   *storage.Storage
    repo    database.PhotoWriter
    reader  database.PhotoReader
}

func New(store *storage.Storage, repo database.PhotoWriter, reader database.PhotoReader) *Pipeline

func (p *Pipeline) Ingest(ctx context.Context, src io.Reader, opts Options) (*database.Photo, error)

var ErrDuplicate = errors.New("photo already exists")
var ErrUnsupportedFormat = errors.New("unsupported file format")
```

### Pipeline steps in `Ingest`

1. Buffer `src` into a temp file (use `os.CreateTemp`, defer cleanup).
2. Compute SHA256 hash + size while writing the temp file.
3. Format detection via `imgconvert.DetectFormat`. Reject `unknown` with `ErrUnsupportedFormat`.
4. Duplicate check via `reader.GetPhotoByHash`. If found and `opts.SkipDuplicates`, return `ErrDuplicate` wrapping the existing photo (caller can decide what to do).
5. Decodable check: call `imgconvert.EnsureDecodable` → returns a path to a JPEG-compatible image (the original for JPEG/PNG/WebP; a temp file for HEIC/RAW). `defer cleanup()`.
6. Extract EXIF from the ORIGINAL (not the converted) path via `exif.Extract`. Use the EXIF `TakenAt` for the path layout.
7. Compute the originals relative path: `storage.OriginalRelPath(meta.TakenAt, opts.Filename)`. If a file already exists at that path (collision on filename + date), append `-<short_hash>` before the extension.
8. Atomically write the original via `store.WriteOriginal(rel, tempFileReader)`.
9. Insert the row via `repo.CreatePhoto` with all metadata; `is_primary = true` for the corresponding `photo_files` row (call `repo.AddPhotoFile`).
10. If `opts.GenerateThumbs`, run `thumb.GenerateAll` against the decodable path. Failures here are logged but do NOT roll back the photo (thumbs can be regenerated later).
11. Return the created `Photo`.

### Rollback / atomicity

If any step from 8 onward fails, delete the on-disk original (`store.DeleteOriginal`) before returning the error. Use a deferred function with a success flag.

### Tests

Use testcontainers + a `t.TempDir()` storage root:
- Ingest a JPEG with full EXIF → record exists, thumbnails generated, hashes match.
- Ingest the same JPEG twice → second call returns `ErrDuplicate` wrapping the first photo; no second file on disk.
- Ingest a JPEG with no EXIF date → falls under `unknown/<file>` path.
- Ingest with `GenerateThumbs=false` → no thumbnails generated.
- Filename collision: two different files with the same name and same EXIF date → second file gets a `-<hash>` suffix and both exist on disk.
