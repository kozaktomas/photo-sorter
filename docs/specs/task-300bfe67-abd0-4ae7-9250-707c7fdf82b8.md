# Smart Albums (Saved Photo Searches)

Add "smart albums" — named, saved photo queries that re-evaluate live whenever opened, so they always reflect the current library state.

## Requirements

- A smart album is a saved filter expression with a user-supplied name. Opening it runs the equivalent of a `GET /api/v1/photos` query with those filters.
- Smart albums live alongside regular albums in the UI but in a separate visual section so users don't confuse them.
- Filters supported (same shape as `GET /api/v1/photos`):
  - `label_uids` (array, all-must-match semantics)
  - `subject_uids` (array, any-must-match semantics)
  - `favorite` (bool)
  - `taken_from`, `taken_to` (date)
  - `min_lat`, `min_lng`, `max_lat`, `max_lng` (geo bbox)
  - `q` (text search string)
  - `sort` (same options as Photos page)

## Database

- Add migration `040_smart_albums.sql`:
  - Table `smart_albums`: `smart_album_uid TEXT PRIMARY KEY` (generate like other UIDs), `name TEXT NOT NULL`, `filters JSONB NOT NULL`, `created_at TIMESTAMP NOT NULL DEFAULT NOW()`, `updated_at TIMESTAMP NOT NULL DEFAULT NOW()`, `created_by_user_uid TEXT NOT NULL REFERENCES users(user_uid)`.
  - Index on `created_by_user_uid` for the list query.

## Endpoints

All endpoints require an authenticated user.

- `GET /api/v1/smart-albums` — list all smart albums. Any role.
- `POST /api/v1/smart-albums` — create. Body: `{ name: string, filters: object }`. HasWriteAccess required.
- `GET /api/v1/smart-albums/{uid}` — get one. Any role.
- `PUT /api/v1/smart-albums/{uid}` — update (name, filters). HasWriteAccess required.
- `DELETE /api/v1/smart-albums/{uid}` — delete. HasWriteAccess required.
- `GET /api/v1/smart-albums/{uid}/photos` — apply the saved filters and return paginated photos (same envelope as `/photos`). Supports `limit`/`offset`/`sort` overrides via query params.

The `filters` JSONB is validated against the same shape as `/photos` query params. Reject unknown keys with 400.

## Frontend

- On the Albums page (`/albums`), add a "Smart albums" section above the regular albums section. Each smart album card shows: name, photo count, edit/delete icons.
  - Photo count: call `/smart-albums/{uid}/photos?limit=0` or add a `count` field in the list response.
- "Create smart album" button opens a modal:
  - Name input.
  - The same filter controls as the Photos page (label combobox, subject combobox, favorite toggle, date pickers, etc.). Reuse `usePhotosFilters` and the Photos page filter components.
  - Save button.
- Click a smart album card → navigate to `/smart-albums/:uid`. Render a `PhotoGrid` with photos fetched from the smart-album photos endpoint. Reuse the Photos page layout (sort selector, pagination). Only the data source differs.
- Edit: same modal pre-filled.
- Delete: confirmation dialog.

## Edge Cases

- Smart album with zero matches: friendly empty state on the detail page.
- Renaming must not change the UID (bookmarks stay valid).
- Filters that reference deleted entities (e.g. a label_uid that was removed): silently skip those filter terms; log a warning.
- Empty filter set: returns all photos. That's intentional (a custom-named "all photos" view).
