# Backup and Restore Documentation

Document the operator workflow for backing up and restoring a photo-sorter installation. The goal is a single page an operator can follow end-to-end with no prior knowledge. Photo-sorter splits its persistent state into two categories:

- **Archival** (must be backed up, cannot be regenerated): the originals tree (`data/originals/YYYY/MM/*` plus XMP sidecars) and the PostgreSQL database (everything in the `photosorter` DB: embeddings, faces, books, users, sessions, era centroids, album/label/marker/subject metadata).
- **Regenerable** (do NOT back up — wastes space and time): `data/cache/thumb/...` thumbnails, persisted HNSW index files (`HNSW_INDEX_PATH`, `HNSW_EMBEDDING_INDEX_PATH`), any LaTeX/PDF temp output.

## Requirements

### New file: `docs/backup.md`
Structure:

1. **Overview** — two sentences explaining the archival vs regenerable split and why.
2. **What to back up** — a table:
   | Path / source | What it contains | Backup? | Notes |
   List `data/originals/`, the PostgreSQL `photosorter` DB, `data/cache/`, HNSW `.hnsw` files, plus any other paths referenced by env vars in `CLAUDE.md` (`STORAGE_ORIGINALS_PATH`, `STORAGE_CACHE_PATH`, `HNSW_INDEX_PATH`, `HNSW_EMBEDDING_INDEX_PATH`).
3. **Backup procedure** — concrete shell commands:
   - Step 1: snapshot the originals tree. Show one example with `rsync -aH --delete` to a remote host and one with `borg create`. Mention that XMP sidecars sit next to the originals and are picked up automatically by a plain file-tree copy.
   - Step 2: dump the metadata DB. Show `photo-sorter db-export -o /backups/photosorter-$(date -u +%Y%m%d-%H%M%S).sql.gz`. Explain that this command is shipped by photo-sorter and wraps `pg_dump`.
   - Step 3: (optional) automate via cron. Provide a single crontab entry doing both steps.
4. **Restore procedure** — concrete shell commands:
   - Step 1: provision PostgreSQL (link to the project README/CLAUDE.md section for the shared instance).
   - Step 2: restore originals tree to the target `STORAGE_ORIGINALS_PATH`.
   - Step 3: `photo-sorter db-import -i <dump-file> --yes` (or `--drop-existing` if the target DB has leftover state).
   - Step 4: start `photo-sorter serve`. HNSW indexes load at startup; if the `.hnsw` files were not restored (recommended), they are rebuilt from the DB on first run.
   - Step 5: regenerate thumbnails. Use `photo-sorter cache build-thumbs` or the admin endpoint `POST /api/v1/process/build-thumbs`. Note that the server will lazily serve missing thumbnails as 404 until the backfill completes; if low traffic, leave it to lazy generation.
   - Step 6: trigger `POST /api/v1/process/rebuild-index` (Rebuild Index button in Settings/Process) if face-search behaves oddly.
5. **Disaster recovery checklist** — short numbered list a sleepy operator can follow at 3am.
6. **What NOT to back up** — explicit list of regenerable paths, with the time/cost of regenerating each so the operator can make an informed call (e.g., "thumbnails for a 50k-photo library: ~20 min on the Pi via `cache build-thumbs --concurrency=4`").

### Style
- Czech is fine for prose IF other docs in `docs/` are in Czech; check first. Default to English to match existing docs.
- Each shell command must be runnable as written. Use `\` line-continuations for long commands rather than wrapping mid-flag.
- No "TODO" or "TBD" markers — if a detail is unknown, ask in the spec, don't ship the doc.

## Edge Cases to Cover in Prose
- Restoring onto a host with a different `STORAGE_ORIGINALS_PATH`: the DB stores relative paths under that root, so the originals just need to live at the new root — no DB rewrite needed. Call this out.
- Restoring a dump that was taken while the server was running: pg_dump is consistent (snapshot isolation), so this is safe; mention it so the operator does not feel compelled to stop the server first.
- Schema version mismatch: if the dump came from a newer photo-sorter than the binary being restored to, `photo-sorter serve` will refuse to start (migrations are forward-only). Tell the operator to upgrade the binary, not downgrade the dump.
