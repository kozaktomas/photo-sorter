# Frontend: User management settings page

Admin-only React page that lists, creates, updates, and disables users. Uses the existing user-management API endpoints (already implemented by an earlier task).

## Requirements

### Files

- `web/src/pages/Settings/Settings.tsx` (new shell with tabs — at first only the "Users" tab).
- `web/src/pages/Settings/Users.tsx` (user CRUD).
- `web/src/pages/Settings/EditUserDialog.tsx` (modal for create/edit).
- `web/src/api/client.ts` — add typed wrappers for `listUsers`, `createUser`, `updateUser`, `setUserPassword`, `setUserDisabled`, `deleteUser`, `getMe`, `changeOwnPassword`.

### Route + access control

- Route `/settings` mounted behind the auth guard.
- The "Users" tab is rendered only if `getMe().role === "admin"`. Non-admins still see the Settings page with the "My profile" tab containing only a "Change password" form.

### Users tab

Layout:
- Header: "Users" title + a "New user" button.
- Table with columns: Username · Display name · Role · Disabled · Last login · Actions.
- Each row has icon buttons: Edit, Set password, Toggle disable, Delete (delete is hidden for the current user and for the last admin — disable client-side and rely on the backend's 400 as the safety net).

Modal (create + edit):
- Fields: username (read-only on edit), display_name, email, role (select admin/editor/viewer).
- Password is only shown on create. On edit, "Set password" is a separate small dialog with single `password` input.

Confirmation dialogs (reuse the existing `ConfirmDialog`) for disable, delete.

### "My profile" tab

- Read-only display of the current user (username, display name, role).
- "Change password" form: `current_password`, `new_password`, `new_password_confirm`. Validates client-side; calls `POST /api/v1/me/password`.

### i18n

Add Czech + English translations in `pages.json`:
- `settings.title`, `settings.users.*`, `settings.profile.*`.

### Layout link

Add a "Settings" link in the main layout sidebar (gear icon), visible to all logged-in users.

### Tests

No React unit tests. Run `cd web && npx tsc --noEmit && npm run lint` and confirm both pass.

### Manual sanity

- Admin creates an editor → editor can log in and is blocked from `/settings/users`.
- Admin can disable + re-enable users.
- Non-admin sees only the profile tab.

## Verification

- Frontend lint + typecheck pass.
- `make build` succeeds.
