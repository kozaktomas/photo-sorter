# Migration export API: complete photo payload, relations, incremental cursor

Kukátko (the successor app) migrates this library **over the HTTP API** — direct database access is off the table. Today's API cannot express a faithful, resumable export. This task closes the metadata gaps; a companion task adds the vector feeds.

The production library is **20,310 photos / 113 labels / 104 people**, so every export path must paginate and resume.

## What is missing today (audited against this repo)

- `GET /api/v1/photos` (`internal/web/handlers/photos.go:431`) has **no `updated_since` filter and no stable cursor** — `database.PhotoFilter` (`internal/database/types.go:406`) offers album/label/subject/favorite/private/archived/taken_from/taken_to/bbox/q only, sorts are `newest`/`oldest`/`name`, and the page cap is 500. A resumable incremental sync is therefore impossible.
- `PhotoResponse` (`handlers/photos.go:148-179`) drops most of the row: **`file_path`, `file_size`, `file_mime`, `file_orientation`, the whole `exif` JSONB, `camera_make`, `lens_model`, `iso`, `aperture`, `exposure`, `focal_length`, `altitude`, `notes`, `taken_at_source`, `created_at`, `updated_at`, `archived_at`**. `lat`/`lng` serialise as `0.0` when NULL, so "no GPS" is indistinguishable from the equator.
- **Which labels a photo carries is unreachable** — there is no `labels` field and no `GET /photos/{uid}/labels`, only the reverse lookup.
- `GET /photos/{uid}/faces` returns the marker's display **name but not `subject_uid`** (`handlers/face_photos.go:169-193`), and no `invalid`/`reviewed`/`score` flags — so marker→person identity cannot be reconstructed reliably.

## Requirements

- `GET /api/v1/photos` gains an **`updated_since=<RFC3339>`** filter and a **stable keyset cursor** (`sort=updated`, `cursor=<last uid>`), so an export resumes exactly where it stopped. Photos modified during a long export must not be skipped or duplicated.
- `PhotoResponse` carries every column listed above. `lat`/`lng`/`altitude` become nullable — `null` means no GPS.
- An **`?include=labels,albums,markers,files`** expansion:
  - `labels`: uid, name, plus `source` and `uncertainty` from `photo_labels`
  - `albums`: uid, title
  - `markers`: uid, **`subject_uid`**, bbox, score, `invalid`, `reviewed`
  - `files`: the `photo_files` stack (RAW/JPEG sidecars, `is_primary`, `role`)
- A **long-lived, read-only API token** for a migration client. Today the only options are a 30-day session cookie or `Authorization: Bearer <sessionID>` (`middleware/session.go:318`); an export job must not depend on a session that expires mid-run. Read-only scope: it must not be able to write.
- Everything stays **read-only** and additive — no change to what the existing UI sees.
- Tests for the cursor (no gaps, no repeats across pages, stable under concurrent writes) and for the payload completeness.

## Notes

- `photos.file_hash` is already lowercase-hex **SHA256** (`internal/storage/hash.go:11`), which is exactly what Kukátko dedups on — keep it exposed.
- Originals already download fine via `GET /api/v1/photos/{uid}/download?original=true`; no change needed there.
- There is no `rating` column; `favorite` and `quality` are the equivalents and are already exposed.
