# Full-text search

Add Czech-aware Postgres full-text search across photo titles, descriptions, and notes. The existing CLIP-based text search stays — this is a complementary, exact-keyword search for when users remember a word from a description.

## Requirements

### Migration `035_photo_fts.sql`

- Add a `GENERATED ALWAYS AS` column on `photos`:

  ```sql
  ALTER TABLE photos ADD COLUMN fts tsvector
    GENERATED ALWAYS AS (
      setweight(to_tsvector('simple', unaccent(coalesce(title, ''))), 'A') ||
      setweight(to_tsvector('simple', unaccent(coalesce(description, ''))), 'B') ||
      setweight(to_tsvector('simple', unaccent(coalesce(notes, ''))), 'C') ||
      setweight(to_tsvector('simple', unaccent(coalesce(file_name, ''))), 'D')
    ) STORED;
  CREATE INDEX photos_fts_idx ON photos USING GIN (fts);
  ```

The `simple` dictionary plus `unaccent` is the right default for Czech: keeps stems intact, treats `Tomáš` and `tomas` as the same token, no stemming surprises. Czech-specific dictionaries exist but require unpacking — keep it simple.

### Repository

- Extend `PhotoFilter.Search`: when non-empty, build a `tsquery` from the user's input:
  - Lowercase + unaccent in the application before passing.
  - Split on whitespace, drop tokens shorter than 2 chars.
  - Join with ` & ` (AND semantics) using `plainto_tsquery('simple', $1)` — let Postgres do the parsing.
  - Add `ORDER BY ts_rank(fts, plainto_tsquery(...)) DESC, ...` when search is active (rank-first, otherwise the existing `taken_at DESC` ordering).

Keep the existing `ILIKE` fallback for very short queries (1 char): switch to `LOWER(title) LIKE LOWER($1) || '%'` to be useful for prefix-typing.

### Tests

- Insert photos with Czech descriptions ("Děti na kole v Praze") → search for "deti" finds it.
- Multi-word AND search ("kolo praha") finds only the photo with both words.
- Empty search returns the existing sort order.

### Frontend

The existing `q` query parameter on `/api/v1/photos` is reused — no UI changes required (the search box already passes it through).
