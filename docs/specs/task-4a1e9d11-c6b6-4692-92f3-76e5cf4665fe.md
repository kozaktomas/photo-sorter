# Add `make deploy` target for production redeploy

Add a `make deploy` target that rebuilds the binary and restarts the production photo-sorter systemd service in a single command.

## Requirements

- New Phony target `deploy` in `Makefile`, listed in the `.PHONY` line and added to the help block.
- Depends on `build` (frontend + Go binary) so the local artifact is fresh before installing.
- Sets `VERSION` for the build to `$(git describe --tags --always --dirty 2>/dev/null || echo dev)` so the deployed binary reports a meaningful version via `GET /api/v1/config` and `photo-sorter version` (don't override if the caller already passed `VERSION=`).
- Installs the freshly built `./photo-sorter` to `/usr/bin/photo-sorter` with `install -m 0755` (uses `sudo`). The install command must be visible (not `@`-prefixed) so the operator sees what's happening.
- Runs `sudo systemctl restart photo-sorter.service` after the binary is in place.
- After restart, polls `http://localhost:8080/api/v1/health` (use `WEB_PORT` env var if set, default 8080) up to 15 times with 1s sleep; succeeds on first 200, fails the target with a clear message if the service never comes up. The health endpoint already exists and requires no auth.
- Prints a final success line that includes the deployed version string and the active service status (one-line `systemctl is-active photo-sorter.service`).
- If any step fails the target exits non-zero so it can be chained safely.

## Implementation Notes

- The systemd unit lives at `deb/photo-sorter.service` (installed to `/etc/systemd/system/photo-sorter.service` via the `.deb`); service user is `photo-sorter`, binary path `/usr/bin/photo-sorter`. No unit changes needed.
- Don't try to be smart about zero-downtime — `systemctl restart` is fine; the service has `Restart=always` and a small `TimeoutStopSec=30s`.
- This is intended to be run on the Pi itself (where the production install lives). Don't add cross-host SSH machinery — operator runs it locally on the host.
- Document the new target in `README.md` under the existing build/test commands section and in `docs/backup.md`-adjacent ops docs if a deploy runbook exists; otherwise add a short note to `README.md` only.
