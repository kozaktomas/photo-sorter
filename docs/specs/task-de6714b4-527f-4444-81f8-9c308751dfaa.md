# Inline rename for albums, labels, books, and smart albums

Replace the "edit name" modal path with double-click inline editing for the most common rename operation.

## Requirements

- New shared `InlineEditableText` component: renders as plain text; on double-click switches to a focused `<input>` pre-filled with the current value; Enter or blur commits, Esc cancels.
- Apply on these entity titles:
  - Albums list (`Albums.tsx`) and album detail header → `PUT /api/v1/albums/{uid}` with `{ title }`
  - Labels list (`Labels.tsx`) and label detail header → `PUT /api/v1/labels/{uid}` with `{ name }`
  - Books list and book editor header → `PUT /api/v1/books/{id}` with `{ title }`
  - Smart albums list and smart album detail header → `PUT /api/v1/smart-albums/{uid}` with `{ name }`
- Permission gate: only render in editable mode when the user has `HasWriteAccess` (admin/editor). Viewers see the same text without the edit affordance.
- Optimistic update: the new value renders immediately; on API failure, roll back and show an error toast (depends on toast task — fall back to `Alert` if not yet shipped).
- Validation: trim; reject empty; if the server returns 409 (label/album name collision) show the toast/Alert with the server's error message.
- Existing "Edit" modal stays for fields other than the title (description, location, etc.) — only the title moves to inline.

## Implementation Notes

- Match the styling of the existing title heading so the visual layout doesn't jump when entering edit mode (same font size, padding, border on focus only).
- Auto-select the full text when entering edit mode so users can just start typing.
