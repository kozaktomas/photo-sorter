# Migration script: PhotoPrism → photo-sorter

A new CLI command that imports an existing PhotoPrism instance into the native photo-sorter schema. One-shot, idempotent, dry-run first. The command reads directly from PhotoPrism's MariaDB and copies originals + thumbnails from the PhotoPrism filesystem layout into the photo-sorter storage layout.

This task assumes the native schema (photos, albums, labels, markers, subjects, users) and storage layer are already in place.

## Requirements

### Command

```bash
go run . migrate-from-photoprism \
  --pp-db "photoprism:photoprism@tcp(mariadb:3306)/photoprism" \
  --pp-originals "/photoprism/originals" \
  --pp-cache "/photoprism/storage/cache" \
  --uploader-username "kozak" \
  [--dry-run] \
  [--skip-thumbs] \
  [--batch-size 200] \
  [--concurrency 4] \
  [--only photos,albums,labels,subjects,markers]
```

Add `cmd/migrate_from_photoprism.go` registered under the root cobra command.

### Stages (run in order; can be limited by `--only`)

For each stage emit progress via the existing `progressbar` library and a summary at the end (counts: read, created, skipped, failed).

1. **users** — no-op (sorter has its own user model; the `--uploader-username` flag picks an existing user to attribute uploads to; create one upfront with the admin tooling if it doesn't exist).

2. **subjects** — read from `subjects` table in PhotoPrism: `subj_uid`, `subj_name`, `subj_type` ("person"/"pet"), `subj_favorite`, `subj_private`, `subj_thumb`. Use `SubjectWriter.EnsureSubject` (idempotent on name).

3. **photos** — read from PhotoPrism `photos` + `files` tables joined on `photo_uid`. For each PhotoPrism photo:
   - Pick the primary file (`file_primary = 1`).
   - Compute the source absolute path: `<pp-originals>/<file_name>` (the `file_name` column already includes the YYYY/MM prefix).
   - Compute SHA256.
   - Skip if `PhotoReader.GetPhotoByHash` already exists (idempotent).
   - Compute destination relative path via `storage.OriginalRelPath(takenAt, basename)`.
   - Copy file via `io.Copy` to `store.WriteOriginal` (atomic).
   - Build the `database.Photo`: map `photo_title`, `photo_description`, `photo_notes`, `photo_lat`, `photo_lng`, `photo_altitude`, `photo_iso`, `photo_f_number`, `photo_exposure`, `photo_focal_length`, `camera_make`, `camera_model`, `photo_taken_at`, `photo_favorite`, `photo_private`. EXIF jsonb left empty for v1 (re-extract on demand later).
   - Insert via `PhotoWriter.CreatePhoto`.
   - For each non-primary file in `files`, also `AddPhotoFile`.
   - Track PhotoPrism `photo_uid` → sorter `uid` mapping in an in-memory `map[string]string` for the next stages.

4. **labels** — read from `labels` (only `label_priority >= 0`, not internal): `label_name`, `label_slug`, `label_priority`. Use `LabelWriter.EnsureLabel`. Then `photos_labels` table: for each pair (photo_uid, label_uid), call `AddPhotoLabel` with `source = "import"` and `uncertainty = label_uncertainty`.

5. **albums** — read from `albums`: `album_title`, `album_description`, `album_type`, `album_favorite`, `album_private`. Insert via `AlbumWriter.CreateAlbum`. Then `photos_albums` table → `AlbumWriter.AddPhotos`. Map PhotoPrism photo UIDs via the mapping built in stage 3.

6. **markers** — read from `markers`: `marker_uid`, `subj_uid`, `file_uid`, `x`, `y`, `w`, `h`, `score`, `marker_invalid`, `marker_review`, `marker_type`. Map file_uid → photo via the `files` table. Insert via `MarkerWriter.CreateMarker` with the mapped `subject_uid`.

7. **thumbnails** (unless `--skip-thumbs`) — for each migrated photo, run `thumb.GenerateAll` against the new destination. This rebuilds the thumb cache in the sorter layout; PhotoPrism's own thumb cache is NOT copied (different layout). Run with the `--concurrency` flag — default 4 workers.

### Dry-run

`--dry-run`: walks everything and prints the counts but does NOT copy files, does NOT touch the DB. Useful to estimate scope and find missing files before committing.

### Resumability

- Photos with an existing matching `file_hash` are skipped (idempotent — re-running picks up where the previous run stopped).
- Subjects/labels/albums lookups by name/slug are idempotent.
- The migration can be interrupted and resumed.

### Logging

- One log line per processed entity at debug level; one summary line per stage at info.
- Skipped vs created vs failed counts printed at end.

### Tests

Integration test using:
- A test MariaDB testcontainer seeded with a minimal PhotoPrism-like schema (3-4 photos, 1 album, 2 labels, 1 subject, 1 marker).
- A `t.TempDir()` originals directory with 3-4 small JPEGs.
- Run the migration, assert the expected rows appear in the sorter Postgres testcontainer and files exist on disk.
- Re-run the migration → no duplicates, all counts zero on the second pass.

## Verification

- `make test` passes.
- `make lint`, `make build-go` pass.
- Dry-run on the production database completes without errors and prints sensible counts.
