# Non-Destructive Photo Editing

Add basic photo editing that never modifies the original file. Edits are stored as parameters and applied at render time to produce derived images.

## Core Principle

The original file in `STORAGE_ORIGINALS_PATH` MUST NEVER be modified by this feature. Edits are stored as parameters in the database; derived JPEGs for thumbnails, downloads, and book exports are generated from the original + edit parameters.

## Operations Supported

- Crop: rectangle with `crop_x`, `crop_y`, `crop_w`, `crop_h` in 0.0-1.0 relative coordinates.
- Rotate: integer degrees, restricted to 0/90/180/270.
- Brightness: float -1.0 to 1.0 (0 = no change).
- Contrast: float -1.0 to 1.0 (0 = no change).

## Database

- Add migration `041_photo_edits.sql`:
  - Table `photo_edits`: `photo_uid TEXT PRIMARY KEY REFERENCES photos(photo_uid) ON DELETE CASCADE`, `crop_x REAL NULL`, `crop_y REAL NULL`, `crop_w REAL NULL`, `crop_h REAL NULL`, `rotation INTEGER NOT NULL DEFAULT 0 CHECK (rotation IN (0, 90, 180, 270))`, `brightness REAL NOT NULL DEFAULT 0.0`, `contrast REAL NOT NULL DEFAULT 0.0`, `updated_at TIMESTAMP NOT NULL DEFAULT NOW()`.
  - A row exists only if a photo has non-default edits; absence means "no edits applied".

## Backend

- `GET /api/v1/photos/{uid}/edits` — returns current edit params (or `{ edits: null }` if none).
- `PUT /api/v1/photos/{uid}/edits` — upsert. Body: `{ crop: { x, y, w, h } | null, rotation: 0|90|180|270, brightness: number, contrast: number }`. Validate ranges; reject out-of-range with 400. HasWriteAccess required.
- `DELETE /api/v1/photos/{uid}/edits` — clear edits (delete the row), revert to original. HasWriteAccess required.

When edits change (PUT or DELETE):
1. Invalidate the photo's cached thumbnails at `<cache>/thumb/<aa>/<bb>/<cc>/<hash>_<size>.jpg` for every registered size.
2. Re-run `internal/thumb.GenerateSizes` synchronously from the post-edit pixel data (decode original, apply crop → rotate → brightness → contrast, then encode for each registered size).
3. Update `updated_at` so HTTP ETags change for thumbnails (or include an edits-version segment in the ETag).

## Image Pipeline

- Implement `internal/imgedit` with a single entry point `ApplyEdits(src image.Image, edits PhotoEdits) image.Image`.
- Order of operations: crop → rotate → brightness → contrast.
- For downloads (`GET /photos/{uid}/download`):
  - If the photo has edits: stream a freshly-rendered JPEG (decode original + apply edits + encode at quality 92). `Content-Disposition: attachment; filename="<original_basename>"`.
  - If no edits: existing behavior (stream the original file with Range support).
  - Accept `?original=true` to always serve the pristine original regardless of edits.
- For book PDF exports (`internal/latex`): when fetching photo files, apply edits before handing pixels to the LaTeX renderer. The book export pipeline already downloads/converts photos — hook in there so books reflect edits.

## Edge Cases

- HEIC/RAW photos: editing requires decoding via `imgconvert` (heif-convert/dcraw). If the binary is missing, return 503 with a clear message ("Editing this format requires heif-convert/dcraw on the server").
- Cropping below 100×100 px after crop: reject with 400.
- Clearing edits on a photo with no edits row: 204 No Content, idempotent.
- Concurrent edits: last-write-wins; PUT updates `updated_at`.

## Out of Scope

- Color balance, exposure curves, vignette, perspective correction.
- Per-channel adjustments, filters, presets.
- Multi-step undo across sessions.
