# Virtualize PhotoGrid for large albums and smart-album results

When a view returns thousands of photos, DOM weight kills scroll performance — especially on the Pi. Virtualize the grid so only visible rows render.

## Requirements

- Replace the current `PhotoGrid` implementation with a virtualized grid using `react-virtuoso` (`VirtuosoGrid`) or `react-window` (`FixedSizeGrid`) — author picks; whichever fits responsive sizing best.
- Visible API of `PhotoGrid` (props, selection mode, click handlers, hover quick-actions slot) must not change — pages should not need edits.
- Responsive column count: grid recomputes columns on container resize (existing breakpoints stay the same).
- Scroll restoration: when navigating back from PhotoDetail to a grid view, restore the previous scroll position (don't snap to top).
- Selection state (`usePhotoSelection`) must survive virtualization — selected cards out of view keep their selected status and re-render correctly when scrolled back into view.
- Lazy image loading (`LazyImage`) continues to work — only items within the virtualization window mount, so off-screen images don't request thumbnails.
- Verify smooth scroll with a 5,000-photo smart album on the Pi (Chromium dev tools timeline).

## Implementation Notes

- The infinite-scroll pagination hook (`usePhotosPagination`) plugs into Virtuoso's `endReached` / `rangeChanged` callbacks instead of a sentinel observer.
- Watch for the bbox-positioning pitfall (`position: relative` parent) — virtualized rows have their own wrappers; verify hover quick-actions and selection overlays still anchor correctly.
- If `react-virtuoso` ends up being too heavy, fall back to a hand-rolled IntersectionObserver windowing approach — but try the lib first.
