# Authorization completeness sweep on all REST routes

Walk every route registered on the HTTP router and verify it has the correct authentication + role middleware applied. Find any route that is unauthenticated when it should not be, or under-privileged (e.g. an admin-only operation reachable by an editor). Fix every clear mistake.

## Scope (files in focus)

- The router wiring file(s) under `internal/web/` where Chi routes are registered.
- Middleware definitions under `internal/web/middleware/` (auth, role, `HasWriteAccess`).
- Every handler file under `internal/web/handlers/` — read each handler to confirm it does not bypass middleware via in-handler escape hatches.
- `docs/API.md` only to compare expected vs actual role gating (the doc is NOT the source of truth — use it as a hint, not a verdict).

Out of scope: the auth + session machinery itself (covered by a separate sweep), and share-link public endpoints (covered by a separate sweep). Verify only that those routes are gated correctly here; do not re-audit internals.

## What to look for

1. **Unauthenticated routes that should be authenticated**
   - The only routes that are intentionally public are: `GET /api/v1/health`, `POST /api/v1/auth/login`, the `/api/v1/public/share/{slug}/*` family. Anything else that ends up outside the protected group is a bug.
   - Static SPA assets and `GET /api/v1/config` may also be public — verify with the existing intent before changing.

2. **Routes with wrong role gate**
   - Admin-only (per `docs/API.md` and CLAUDE.md): all `/api/v1/users/*` mutations, `DELETE /api/v1/photos/batch/purge`, `GET /api/v1/audit-log`, `POST /api/v1/process/build-thumbs`. Confirm each is actually behind an admin middleware, not just authenticated.
   - HasWriteAccess (admin + editor): album/photo/label/subject mutations, book mutations, EXIF edits, photo edits, share-link mint/list/revoke, smart-album mutations. A viewer must not be able to mutate these.
   - Read-only endpoints (any authenticated user): listing + detail + thumbnail / download endpoints, audit-log-aware viewers — verify they do NOT accidentally require write access.

3. **In-handler authorization bypass**
   - Handlers that compute permissions themselves (rather than via middleware) — verify the check is correct and cannot be skipped via missing parameters or default branches.
   - Mutating operations that take a target user / album / photo UID — confirm cross-tenant boundaries make sense (or document that this is a single-tenant deployment if that is the intent).

4. **Method confusion**
   - Routes registered for `GET` but performing mutations (or vice versa).
   - Routes that respond to `OPTIONS`/`HEAD` outside the protected group when the resource is otherwise auth-gated.

5. **Audit log coverage gap**
   - Every mutating endpoint should write a row to `audit_log` (best-effort, WARN-log on failure). Find any mutating endpoint that is silent.
   - Batch operations should write a single row with `metadata.count`, not one row per item.

## How to work

1. Build a table in scratch (or just mentally): for each route, expected gate vs actual gate. Do not skip routes — a single missed route is the whole reason for this sweep.
2. For each confirmed mismatch: focused commit (`fix(auth): require admin on /api/v1/...` or similar) with a short, accurate message.
3. For ambiguous cases (e.g. "should this be admin or editor?"): pick the more restrictive of the two if it does not break a documented workflow; otherwise leave as-is and note in `TODO.md` under `## Authorization sweep — YYYY-MM-DD`.
4. Add tests where the fix is a meaningful change of behavior (a previously-unauthenticated route should have a test that 401s without a session).
5. If `docs/API.md` is wrong about an endpoint's role, leave a one-line note in `TODO.md` — the dedicated API doc task will sweep it.

## Verification

- `make lint` must pass.
- `make test` must pass.
- `make check` runs the full gate.
- Manually verify (via the test suite or a quick curl) that at least one fixed route now returns the expected 401/403.

## Done when

- Every route on the router has been visited and either confirmed correct or fixed.
- A short summary in the final task report lists: routes audited, routes changed, routes deferred to `TODO.md` with reasoning.
- `make check` is green.
