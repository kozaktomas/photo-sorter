# Fix CI failure: pg_dump / server version mismatch in TestPgDump_subprocess

The `test` job in `.github/workflows/test.yml` is failing on `main`. The failing test is `TestPgDump_subprocess` in `cmd/backup_test.go`.

## Root cause

`TestPgDump_subprocess` starts a disposable Postgres container pinned to `postgres:17-alpine` (see `cmd/backup_test.go` around line 386) and then runs the real `pg_dump` binary found on `PATH` against it. The CI job runs on `ubuntu-latest`, whose bundled `pg_dump` client is version 16.14. `pg_dump` refuses to dump a server that is newer than the client, so the subprocess exits with status 1:

```
pg_dump: error: aborting because of server version mismatch
pg_dump: detail: server version: 17.10; pg_dump version: 16.14 (Ubuntu 16.14-1.pgdg24.04+1)
```

The test itself and the production behaviour are correct — the problem is that the CI runner's `pg_dump` client is older than the Postgres 17 server the test (and production) uses. The production Docker image bundles a Postgres 17 client, so CI must match.

## Requirements

- Make the `test` job in `.github/workflows/test.yml` provide a `pg_dump` (and `pg_restore`, since `db-import` / restore paths use it) client of version **17 or newer** on `PATH` before `go test` runs, so `TestPgDump_subprocess` passes instead of failing on a version mismatch.
- The recommended approach is to add a step to the `test` job that installs the PostgreSQL 17 client tools from the official PGDG apt repository (`postgresql-client-17`) and ensures its binaries are ahead of the Ubuntu-bundled version 16 client on `PATH`. Ubuntu keeps versioned client binaries under `/usr/lib/postgresql/<version>/bin`; make sure the version 17 `pg_dump`/`pg_restore` is the one resolved by `exec.LookPath` in the test.
- Do NOT downgrade the test's Postgres container from `postgres:17-alpine`. The library and production run Postgres 17; the fix is to align the CI client to the server, not the other way around.
- The `TestPgDump_subprocess` test must actually RUN in CI (it skips itself when `pg_dump` or `docker` is not on `PATH`) and must pass. Confirm the fix does not accidentally leave `pg_dump` off `PATH`, which would silently skip the test rather than exercise it.
- Keep the change scoped to CI configuration. Do not modify `cmd/backup_test.go`, `cmd/db.go`, or the `dumpDatabase` implementation unless a code change is genuinely required to make the correct client version resolve.

## Verification

- The `test` job of the Tests workflow passes end-to-end.
- `TestPgDump_subprocess` runs (not skipped) and passes: the dump completes and contains the seeded `backup_marker` table.
