# Refresh docs/architecture.md

Bring `docs/architecture.md` in sync with the current system design. This document explains the overall shape of the application: components, packages, data flow, and persistence model. It is the reference a new developer (human or AI) reads first to understand how the pieces fit together.

## Scope

- File to edit: `docs/architecture.md` only.
- Source of truth: directory layout under `internal/` and `cmd/`, the migrations under `internal/database/postgres/migrations/`, and the route wiring under `internal/web/`.

## What to verify and update

1. **System diagram / component overview** — one Go binary + Postgres (pgvector) + external embeddings service. PhotoPrism is no longer a runtime dependency.
2. **Package list** — every `internal/*` package must exist with an accurate one-line description. Add any newly added packages (look for things like `internal/audit/`, `internal/imgedit/`, `internal/trash/`, `internal/verify/`, etc.) and drop any deleted ones.
3. **Upload pipeline** — buffer → SHA256 → format detect → exact-dup → decode (heif-convert/dcraw/native) → EXIF (exiftool + Go fallback) → near-duplicate scan (pHash + embedding, gated by env) → write original → DB rows → thumbnails → optional embeddings + face detection.
4. **Storage model** — originals at `<originals>/YYYY/MM/<filename>` (PhotoPrism-compatible); thumbnail cache at `<cache>/thumb/<aa>/<bb>/<cc>/<hash>_<size>.jpg`; cache is regenerable via `cache build-thumbs`.
5. **Database schema** — confirm every table is listed: users, sessions, photos, photo_files, photo_phashes, albums + album_photos, labels + photo_labels, subjects, markers, embeddings, faces, faces_processed, era_embeddings, photo_books, book_chapters, book_sections, section_photos, book_pages, page_slots, text_versions, text_check_results, album_share_links, smart_albums, photo_edits, audit_log. Cross-check against `internal/database/postgres/migrations/`.
6. **Similarity search** — must mention pgvector HNSW with `vector_cosine_ops`, `SET LOCAL hnsw.ef_search = 100`, and that no in-memory vector data is held by the app. Link to `docs/similarity-search.md` for depth.
7. **Web layer** — Chi router, embedded SPA via `go:embed`, session cookies persisted in Postgres, security headers (CSP / X-Frame-Options / X-Content-Type-Options), CORS allowlist behavior.
8. **Background jobs** — SSE job managers for sort, upload, process (embeddings/faces), book export, build-thumbs. Hourly auto-purge daemon for trash.
9. **Audit log** — every mutating handler appends to `audit_log` via `internal/audit/`; write failures WARN-log and do not fail the request.
10. **Non-destructive edits** — `photo_edits` row drives runtime render in `internal/imgedit/`; thumbnails are regenerated synchronously on save.
11. **MCP server** — mounted at `/mcp/sse` + `/mcp/message` on the same HTTP server when `MCP_API_TOKEN` is set; tool surface enumerated in `internal/mcp/`.
12. **AI providers** — interface in `internal/ai/`, implementations for OpenAI, Gemini, Ollama, llama.cpp; pricing in `internal/config/prices.yaml`.

## Rules

- Code is the source of truth. Add what is missing, remove what no longer exists, fix what is wrong.
- Do not invent components, packages, or tables. Grep before you write.
- Keep section structure mostly intact; do surgical edits.
- Prefer concise prose + bulleted lists. No code blocks unless they add unique value.
- Link forward to deeper docs (`docs/API.md`, `docs/markers.md`, `docs/similarity-search.md`, `docs/photo-book.md`, etc.) instead of duplicating.
