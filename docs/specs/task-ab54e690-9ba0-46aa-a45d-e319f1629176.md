# Backup CLI + scheduled job

A first-class backup command that creates a single timestamped backup containing:
1. The `originals/` directory (the only on-disk asset that can't be regenerated).
2. A `pg_dump` of the photo-sorter Postgres database (schema + data, including pgvector).

The thumbnail cache is INTENTIONALLY excluded — it can be regenerated from the originals via the thumbnail backfill job.

## Requirements

### Command

```bash
go run . backup \
  --output /backup \
  [--originals-path /data/originals] \
  [--db-url "postgres://..."] \
  [--keep 14] \
  [--compress gzip|zstd] \
  [--skip-originals] [--skip-db]
```

Add `cmd/backup.go`.

### What it produces

`<output>/photo-sorter-<YYYYMMDD-HHMMSS>/`:
- `metadata.json` — `{ created_at, sorter_version, db_size_bytes, originals_bytes, file_count }`
- `db.sql.zst` (or `.gz`) — `pg_dump --format=plain --no-owner --no-privileges` piped through compressor.
- `originals.tar.zst` (or `.tar.gz`) — streamed tar of the originals directory, preserving relative paths.

The two artifacts are siblings inside the timestamped folder so the user can restore selectively.

### pg_dump

- Invoke the `pg_dump` binary via `exec.CommandContext`. The Dockerfile already ships `postgresql-client` if the compose task above added it; otherwise add it now (apt: `postgresql-client`).
- 30-minute timeout.
- Use the `DATABASE_URL` env var if `--db-url` is not specified.

### tar

- Stream the tar with `archive/tar` in Go (no `tar` binary dep).
- Walk the originals directory with `filepath.Walk` — only include regular files. Resolve symlinks to their target file contents.
- Apply the chosen compressor: `klauspost/compress/zstd` (already a transitive dep) or `compress/gzip` (stdlib).
- Set `Header.Name` to the path relative to the originals root.

### Retention (`--keep N`)

After a successful backup, list immediate children of `--output` matching the `photo-sorter-*` pattern, sort by timestamp DESC, and delete everything past the Nth. `0` disables pruning.

### Atomicity

- Write the timestamped folder first to `<output>/.photo-sorter-<ts>.tmp/`, then atomically rename to the final name when done.
- On failure, leave the `.tmp` folder for inspection unless `--cleanup-on-failure` is passed.

### Progress

- For db dump: report the dumped size when complete.
- For originals: print a small progress log every N files (default 500) and a final summary `{file_count, total_bytes}`.

### Cron / scheduler integration

Add a sample systemd service + timer in `deploy/systemd/`:
- `photo-sorter-backup.service` — oneshot running `photo-sorter backup --output /var/backups/photo-sorter --keep 14`.
- `photo-sorter-backup.timer` — daily at 03:00.

Add a section in `CLAUDE.md` (or `docs/deployment.md` if it exists, otherwise extend `README.md`) showing how to install the timer.

### Tests

- `t.TempDir()` originals with 3-4 small files → run backup with `--skip-db` → tarball extracts to identical files (use `archive/tar` to walk).
- `--keep 2` after 5 invocations → 2 directories remain, the 3 oldest are gone.
- pg_dump invocation is mocked via `--skip-db` in the integration test; the `pg_dump` subprocess is exercised in a separate test that uses the testcontainers Postgres URL and skips if `pg_dump` is missing.
