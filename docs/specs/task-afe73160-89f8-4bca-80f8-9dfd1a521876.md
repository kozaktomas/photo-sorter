# Face handlers refactor

Rewire the face-related HTTP handlers from PhotoPrism marker/subject calls (`pp.GetPhotoMarkers`, `pp.GetSubject`, `pp.UpdateMarker`, `pp.CreateMarker`, `pp.UpdateSubject`, `pp.GetSubjects`) to the native `MarkerReader`/`MarkerWriter` and `SubjectReader`/`SubjectWriter` repositories.

The pgvector `faces` table and HNSW index (face embeddings, the `internal/database/hnsw_index.go` machinery) remain unchanged. Only the relational marker/subject data source changes.

## Requirements

### Files to modify

- `internal/web/handlers/faces.go`
- `internal/web/handlers/face_apply.go`
- `internal/web/handlers/face_match.go`
- `internal/web/handlers/face_outliers.go`
- `internal/web/handlers/face_photos.go`
- `internal/web/handlers/face_helpers.go`
- `internal/web/handlers/subjects.go`
- All matching `*_test.go`

### Endpoints (paths unchanged)

- `GET /api/v1/subjects` → `SubjectReader.ListSubjects` (replaces `pp.GetSubjects`).
- `GET /api/v1/subjects/{uid}` → `SubjectReader.GetSubject` (replaces `pp.GetSubject`).
- `PUT /api/v1/subjects/{uid}` → `SubjectWriter.UpdateSubject` (replaces `pp.UpdateSubject`).
- `GET /api/v1/photos/{uid}/faces` → builds the combined response (faces from pgvector + markers from `MarkerReader.ListMarkersForPhoto`, joined by IoU just like today). The IoU + suggestion logic in `face_helpers.go` stays — only the marker fetch changes.
- `POST /api/v1/faces/match` → finds nearby face embeddings via HNSW, joins to markers via `MarkerReader.ListMarkersForPhoto` for the candidates' photos.
- `POST /api/v1/faces/apply` — actions `create_marker`, `assign_person`, `unassign_person`:
  - `create_marker`: `MarkerWriter.CreateMarker` + `MarkerWriter.AssignSubject` if `subject_uid` given.
  - `assign_person`: `MarkerWriter.AssignSubject`.
  - `unassign_person`: `MarkerWriter.UnassignSubject`.
- `POST /api/v1/faces/outliers` → unchanged shape, sourced from native markers + pgvector embeddings.

### Subject creation flow

When `face_apply` is called with `subject_uid` empty but a `subject_name` field is present, call `SubjectWriter.EnsureSubject(name, "person")` to create or find the subject, then assign. This replaces the equivalent PhotoPrism flow.

### Coordinate handling

The existing `convertPixelBBoxToDisplayRelative` helper in `face_helpers.go` stays as-is. The native `Marker` already stores display-relative `x, y, w, h` (0-1), so no conversion is needed when matching with embedding face bboxes.
