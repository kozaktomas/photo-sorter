# Soft-delete trash with 30-day grace period

The `photos.archived_at` column already exists (set by `archive` batch endpoint). Add the missing pieces: a trash listing endpoint, a restore action, a hard-delete action for items already in trash, and an automatic purge of items older than 30 days.

## Requirements

### Endpoints

- `GET /api/v1/photos/trash` → calls `PhotoReader.ListPhotos` with `Archived: ptr(true)`. Same filters and sorting as the main photo list. Pagination identical.
- `POST /api/v1/photos/batch/restore` (already defined in the photo-update task) — verify it lives here too if not yet implemented.
- `POST /api/v1/photos/batch/purge` — body `{ photo_uids: [...] }`. For each UID:
  1. Verify it is currently archived. If not, skip with error.
  2. Call `PhotoWriter.DeletePhoto(uid)` (hard delete).
  3. Delete originals + thumbnails from disk (`store.DeleteOriginal`, `store.DeleteThumb` for all sizes).
  4. Delete the corresponding rows from `embeddings`, `photo_phashes`, `markers` (cascades via FK).

### Auto-purge daemon

Add a small background ticker in the server startup (`cmd/serve.go`) that runs every hour and hard-deletes archived photos whose `archived_at` is older than `TRASH_RETENTION_DAYS` (default 30). Log how many were purged. Make the retention configurable via env var.

Reuse the same purge logic as the batch endpoint — extract into a helper `func PurgePhoto(ctx, uid, store, repo) error`.

### Authorization

- `GET /trash`: any role.
- Batch restore: editor or admin (`HasWriteAccess`).
- Batch purge: admin only.

### Tests

- Archive then list trash → photo appears.
- Restore via batch endpoint → no longer in trash.
- Purge a non-archived photo → error in the per-photo report; row still exists.
- Purge an archived photo → row, files, thumbs, embeddings all gone.
- Auto-purge: insert a photo with `archived_at = NOW() - 31 days`, run the purge helper, verify it is gone.

### Frontend hook

This task does NOT add the UI. Just expose the endpoint contract. UI is part of the frontend rewire task.
