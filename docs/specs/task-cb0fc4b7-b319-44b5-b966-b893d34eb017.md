# Photo serve HTTP handlers (own backend)

Replace the `internal/web/handlers/photos.go` PhotoPrism-backed read paths with native handlers that serve photos from the local Postgres `photos` table + filesystem storage. Existing HTTP routes stay the same so the frontend continues to work.

Out of scope: photo PUT/update (separate task), upload (separate task), face/album/label handlers.

## Requirements

### Files to modify

- `internal/web/handlers/photos.go` — rewrite the GET handlers.
- `internal/web/handlers/photos_test.go` — update.

### Handler dependencies

The `BooksHandler`-style pattern: introduce a `PhotosHandler` struct holding:
- `reader database.PhotoReader`
- `store *storage.Storage`
- `pp *photoprism.Client` — KEEP this for now; later handlers in this file may still need it (faces). Only the GET-photos endpoints stop using it in this task.

Update the route registration in `internal/web/router.go` (or wherever the photos routes are wired) to inject these dependencies. Match the wiring style used by `BooksHandler`.

### Endpoints to rewrite (native data source)

#### GET `/api/v1/photos`
Lists photos with filtering + pagination. Query params:
- `album_uid` (string)
- `label_uid` (repeatable, AND)
- `subject_uid` (repeatable)
- `favorite` (bool)
- `private` (bool)
- `archived` (bool, default false)
- `taken_from`, `taken_to` (RFC3339)
- `min_lat`, `min_lng`, `max_lat`, `max_lng` (all four required to filter by bbox)
- `q` (search string)
- `sort` (`newest`/`oldest`/`name`)
- `limit` (default 50, max 500), `offset`

Translate into `database.PhotoFilter` and call `reader.ListPhotos`.

Response shape: `{ "photos": [Photo...], "total": N, "limit": L, "offset": O }`. The `Photo` JSON keys match the existing API (snake_case) — see the current `types.go` and the existing frontend `types/index.ts` for the contract. If field names differ between old PhotoPrism `Photo` and new `database.Photo`, map them in the handler.

#### GET `/api/v1/photos/{uid}`
Returns a single photo (404 if missing or archived unless `?include_archived=true`).

#### GET `/api/v1/photos/{uid}/thumb/{size}`
- Resolve the photo, read `file_hash`.
- Build the thumb path via `storage.ThumbRelPath(hash, size)`.
- If the thumb doesn't exist on disk, return 404 (regeneration is a separate concern handled by `process` job).
- Open the file via `store.OpenThumb`, set `Content-Type: image/jpeg`, `Cache-Control: public, max-age=31536000, immutable`, ETag (`"sha:<hash>:<size>"`), and stream.

#### GET `/api/v1/photos/{uid}/download`
- Resolve photo + primary `photo_files` row.
- Open the original via `store.OpenOriginal`.
- Set `Content-Type` from the photo `file_mime`, `Content-Disposition: attachment; filename="<file_name>"`, `Content-Length`.
- Support HTTP `Range` requests (use `http.ServeContent` with an `os.File`).

### Authorization

All endpoints stay behind the existing session-auth middleware. Role checks come in a later task; for now treat all logged-in users as readers.

### Tests

- List filters: by date range, search, bbox.
- Single photo: 404 for archived (default), 200 with `?include_archived=true`.
- Thumb: 200 with correct headers when file exists; 404 when missing.
- Download: full response when no `Range`; partial response with status 206 when `Range: bytes=0-99`.

Use the existing test helpers in `testutil_test.go` (in-memory storage + testcontainers DB).

- `make test` passes.

- Manual sanity: `go run . serve` + curl `/api/v1/photos` returns rows that exist in the DB (with no PhotoPrism call).
